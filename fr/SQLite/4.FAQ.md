# Questions Fréquemment Posées (FAQ) sur SQLite

## 1. Comment créer un champ AUTOINCREMENT ?

**Réponse courte** : Une colonne déclarée `INTEGER PRIMARY KEY` s'auto-incrémente automatiquement.

**Réponse détaillée** : 
Lorsque vous déclarez une colonne comme `INTEGER PRIMARY KEY`, chaque fois que vous insérez `NULL` dans cette colonne, SQLite le convertit automatiquement en un entier supérieur de 1 à la plus grande valeur existante dans cette colonne, ou 1 si la table est vide.

```sql
CREATE TABLE t1(
    a INTEGER PRIMARY KEY,
    b INTEGER
);

INSERT INTO t1 VALUES(NULL,123); -- 'a' sera automatiquement 1
```

Pour garantir que les clés soient uniques pendant toute la durée de vie de la table (même après suppression), ajoutez le mot-clé `AUTOINCREMENT` :

```sql
CREATE TABLE t1(
    a INTEGER PRIMARY KEY AUTOINCREMENT,
    b INTEGER
);
```

Utilisez la fonction `sqlite3_last_insert_rowid()` pour obtenir la clé entière de la dernière opération d'insertion.

## 2. Quels types de données SQLite supporte-t-il ?

SQLite utilise un **typage dynamique**. Le contenu peut être stocké sous forme de :
- INTEGER (entier)
- REAL (nombre réel/flottant)
- TEXT (texte)
- BLOB (objet binaire)
- NULL (valeur nulle)

## 3. SQLite me permet d'insérer une chaîne dans une colonne de type entier !

C'est une **fonctionnalité**, pas un bug. SQLite utilise le typage dynamique et n'impose pas de contraintes strictes de type de données. Cependant, SQLite utilise le type déclaré d'une colonne comme indication pour convertir les valeurs si possible (affinité de type).

Par exemple, si une colonne est de type INTEGER et que vous essayez d'y insérer une chaîne, SQLite tentera de convertir la chaîne en entier. S'il y parvient, il insère l'entier ; sinon, il insère la chaîne.

## 4. Pourquoi SQLite ne me permet-il pas d'utiliser '0' et '0.0' comme clé primaire sur deux lignes différentes ?

Ce problème se produit lorsque votre clé primaire est de type numérique. SQLite considère que '0' et '0.0' sont la même valeur car ils sont égaux numériquement. 

**Solution** : Changez le type de données de votre clé primaire en TEXT.

## 5. Plusieurs applications peuvent-elles accéder simultanément au même fichier de base de données ?

Oui, plusieurs processus peuvent avoir la même base de données ouverte simultanément. Plusieurs processus peuvent effectuer des requêtes `SELECT` en même temps. Cependant, **un seul processus peut effectuer des modifications** à la fois.

SQLite utilise des verrous lecteur/écrivain pour contrôler l'accès. Soyez prudent si la base de données est sur un système de fichiers NFS, car le verrouillage de fichiers via `fcntl()` est souvent défectueux sur NFS.

## 6. SQLite est-il compatible avec les threads (threadsafe) ?

Oui, SQLite est compatible avec les threads, mais doit être compilé avec la macro préprocesseur `SQLITE_THREADSAFE` définie à 1. Les binaires précompilés pour Windows et Linux sont compilés de cette manière.

Vous pouvez vérifier si votre bibliothèque SQLite est threadsafe en appelant la fonction `sqlite3_threadsafe()`.

**Note importante** : Sous Unix, vous ne devez pas transporter une base de données SQLite ouverte à travers un appel système `fork()` dans le processus fils.

## 7. Comment lister toutes les tables/index contenus dans une base de données SQLite ?

Dans l'interface en ligne de commande :
- `.tables` : Liste toutes les tables
- `.schema` : Affiche le schéma complet de la base

Depuis un programme C/C++ ou un script :
```sql
-- Liste des tables
SELECT name FROM sqlite_schema WHERE type='table' ORDER BY name;

-- Liste des index
SELECT name FROM sqlite_schema WHERE type='index' ORDER BY name;
```

Note : Dans les versions antérieures à 3.33.0, la table système s'appelait `sqlite_master` au lieu de `sqlite_schema`.

## 8. Existe-t-il des limites de taille connues pour les bases de données SQLite ?

Consultez la page [limits.html](https://www.sqlite.org/limits.html) pour une discussion complète sur les limites de SQLite.

Principales limites :
- Taille maximale de la base de données : **140 téraoctets**
- Longueur maximale d'une chaîne : **1 milliard d'octets**
- Nombre maximal de lignes dans une table : **2^64** (limité par l'espace disque)

## 9. Quelle est la taille maximale d'un VARCHAR dans SQLite ?

SQLite **n'impose aucune limite** à la longueur d'un VARCHAR. Vous pouvez déclarer `VARCHAR(10)` et SQLite stockera sans problème une chaîne de 500 millions de caractères. Le contenu n'est jamais tronqué.

SQLite considère le type de colonne `"VARCHAR(N)"` comme équivalent à `"TEXT"`, quelle que soit la valeur de N.

## 10. SQLite supporte-t-il le type BLOB ?

Oui, SQLite vous permet de stocker des données BLOB dans n'importe quelle colonne, même celles déclarées pour contenir un autre type. Les BLOB peuvent même être utilisés comme clés primaires.

## 11. Comment ajouter, supprimer ou renommer des colonnes dans une table existante ?

SQLite dispose d'un support limité de `ALTER TABLE` qui vous permet d'ajouter, renommer ou supprimer des colonnes, ou de changer le nom d'une table.

Pour des modifications plus complexes de la structure d'une table, vous devrez la recréer :
1. Sauvegardez les données existantes dans une table temporaire
2. Supprimez l'ancienne table
3. Créez la nouvelle table
4. Copiez les données depuis la table temporaire

## 12. J'ai supprimé beaucoup de données mais le fichier de base de données n'a pas réduit. Est-ce un bug ?

Non, ce n'est pas un bug. Lorsque vous supprimez des informations, l'espace disque inutilisé est ajouté à une "liste libre" interne et est réutilisé lors des prochaines insertions.

Pour réduire la taille du fichier de base de données, exécutez la commande `VACUUM` :
```sql
VACUUM;
```

Cette commande reconstruit la base de données à partir de zéro, ce qui peut prendre du temps et utiliser jusqu'au double de l'espace disque temporaire.

## 13. Puis-je utiliser SQLite dans mon produit commercial sans payer de redevances ?

**Oui**. SQLite est dans le **domaine public**. Aucune réclamation de propriété n'est faite sur une partie quelconque du code. Vous pouvez faire tout ce que vous voulez avec.

## 14. Comment utiliser une chaîne littérale contenant une apostrophe (') ?

Selon la norme SQL, les apostrophes dans les chaînes sont échappées en plaçant deux apostrophes consécutives :
```sql
INSERT INTO xyz VALUES('5 O''clock');
```

## 15. Qu'est-ce qu'une erreur SQLITE_SCHEMA et pourquoi l'obtiens-je ?

Une erreur `SQLITE_SCHEMA` est retournée lorsqu'une instruction SQL préparée n'est plus valide et ne peut pas être exécutée. Cela se produit généralement lorsque le schéma de la base de données change après la préparation de l'instruction.

**Solution** : Utilisez toujours `sqlite3_prepare_v2()` au lieu de `sqlite3_prepare()`. L'interface `sqlite3_prepare_v2()` crée une instruction préparée qui se recompile automatiquement si le schéma change.

## 16. J'obtiens des avertissements du compilateur lors de la compilation de SQLite. Est-ce un problème ?

La qualité de SQLite est assurée par des **tests à couverture complète**, pas par l'absence d'avertissements du compilateur. La suite de tests de SQLite exécute des centaines de millions de tests impliquant des milliards d'instructions SQL avant chaque version.

Les avertissements du compilateur surviennent généralement avec des compilateurs ou des options que les développeurs de SQLite n'utilisent pas eux-mêmes.

## 17. La correspondance insensible à la casse des caractères Unicode ne fonctionne pas.

La configuration par défaut de SQLite ne supporte la correspondance insensible à la casse que pour les caractères ASCII. Le support Unicode complet nécessiterait des tables et une logique qui doubleraient presque la taille de la bibliothèque.

**Solutions** :
- Utilisez l'extension ICU incluse dans le code source de SQLite
- Surchargez la séquence de classement `NOCASE` intégrée avec `sqlite3_create_collation()`
- Surchargez les fonctions intégrées `like()`, `upper()` et `lower()` avec `sqlite3_create_function()`

## 18. Les INSERT sont très lents - je ne peux faire que quelques dizaines d'INSERT par seconde

En réalité, SQLite peut facilement effectuer 50 000 INSERT ou plus par seconde sur un ordinateur de bureau moyen. Cependant, il ne peut effectuer que quelques dizaines de **transactions** par seconde, car la vitesse des transactions est limitée par la vitesse de rotation du disque.

**Solution** : Regroupez plusieurs instructions INSERT dans une seule transaction :
```sql
BEGIN;
INSERT INTO table VALUES (...);
INSERT INTO table VALUES (...);
-- ... plus d'INSERT
COMMIT;
```

Alternative (moins sûre) : `PRAGMA synchronous=OFF` (risque de corruption en cas de panne de courant).

## 19. J'ai accidentellement supprimé des informations importantes. Comment les récupérer ?

Si vous avez une copie de sauvegarde, récupérez les informations à partir de celle-ci.

Sans sauvegarde, la récupération est très difficile. Certaines données sous forme de chaîne peuvent être trouvées dans un dump binaire du fichier de base de données brut. Cependant :
- Si SQLite a été compilé avec `SQLITE_SECURE_DELETE`, la récupération est impossible
- Si vous avez exécuté `VACUUM` depuis la suppression, la récupération est impossible

## 20. Qu'est-ce qu'une erreur SQLITE_CORRUPT ? Que signifie "malformé" ?

Une erreur `SQLITE_CORRUPT` est retournée lorsque SQLite détecte une erreur dans la structure, le format ou d'autres éléments de contrôle du fichier de base de données.

**Important** : SQLite ne corrompt pas les fichiers de base de données sans aide externe. Même en cas de panne système ou de coupure de courant, vos données restent sécurisées.

Les causes externes de corruption incluent :
- Bugs matériels (mémoire défectueuse, erreurs de disque)
- Bugs du système d'exploitation
- Accès concurrent non sécurisé (partage réseau problématique)

Utilisez `PRAGMA integrity_check` pour une vérification approfondie de l'intégrité de la base.

## 21. SQLite supporte-t-il les clés étrangères ?

À partir de la version 3.6.19 (2009-10-14), SQLite supporte les contraintes de clé étrangère. Cependant, **l'application des contraintes de clé étrangère est désactivée par défaut** pour des raisons de compatibilité ascendante.

Pour activer l'application des clés étrangères :
```sql
PRAGMA foreign_keys=ON;
```

## 22. Où est passée ma base de données ? (Ou : Comment ma base de données est-elle devenue vide ?)

À moins d'être ouverte avec des indicateurs spécifiques, une base de données SQLite est créée si elle n'existe pas déjà. Les bases nouvellement créées sont initialement vides.

Cela peut confondre les personnes qui ouvrent accidentellement différents fichiers de base de données dans différents contextes, en raison soit :
- D'une faute de frappe dans le nom du fichier
- De l'utilisation d'un chemin relatif avec des répertoires de travail différents
