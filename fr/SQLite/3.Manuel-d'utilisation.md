# Manuel d'utilisation de SQLite

## Interface en ligne de commande

L'interface en ligne de commande (CLI) de SQLite est l'outil principal pour interagir avec les bases de données SQLite.

### Démarrage

Pour démarrer SQLite CLI :
```bash
sqlite3 [nom_fichier_base.db]
```

Si le fichier de base de données n'existe pas, il sera créé automatiquement.

### Commandes dot (commandes spéciales)

Les commandes commençant par un point (`.`) sont des commandes spéciales du shell SQLite :

- `.help` : Affiche l'aide
- `.tables` : Liste toutes les tables
- `.schema [table]` : Affiche le schéma de la base ou d'une table spécifique
- `.dump [table]` : Exporte la base de données en SQL
- `.output fichier` : Redirige la sortie vers un fichier
- `.read fichier` : Exécute des commandes SQL depuis un fichier
- `.mode [mode]` : Définit le mode d'affichage (csv, html, json, line, list, tabs, etc.)
- `.headers on|off` : Active/désactive l'affichage des en-têtes de colonnes
- `.quit` ou `.exit` : Quitte le shell

### Exemples d'utilisation

#### Création d'une base de données simple
```sql
-- Création d'une table
CREATE TABLE contacts (
    id INTEGER PRIMARY KEY,
    nom TEXT NOT NULL,
    email TEXT,
    telephone TEXT
);

-- Insertion de données
INSERT INTO contacts (nom, email, telephone) 
VALUES ('Jean Dupont', 'jean@example.com', '0123456789');

-- Requête de sélection
SELECT * FROM contacts;
```

#### Import/Export de données
```bash
-- Export en CSV
.mode csv
.headers on
.output contacts.csv
SELECT * FROM contacts;
.output stdout

-- Import depuis CSV
.mode csv
.import contacts.csv contacts
```

## API C/C++

### Concepts de base

L'API C de SQLite suit ces étapes principales :

1. **Ouverture de la base** : `sqlite3_open()`
2. **Compilation de la requête** : `sqlite3_prepare_v2()`
3. **Exécution de la requête** : `sqlite3_step()`
4. **Libération des ressources** : `sqlite3_finalize()`
5. **Fermeture de la base** : `sqlite3_close()`

### Exemple minimal en C
```c
#include <sqlite3.h>
#include <stdio.h>

int main() {
    sqlite3 *db;
    char *err_msg = 0;
    
    // Ouverture de la base de données
    int rc = sqlite3_open("test.db", &db);
    if (rc != SQLITE_OK) {
        fprintf(stderr, "Impossible d'ouvrir la base: %s\n", sqlite3_errmsg(db));
        sqlite3_close(db);
        return 1;
    }
    
    // Exécution d'une requête simple
    char *sql = "CREATE TABLE IF NOT EXISTS users(id INTEGER PRIMARY KEY, name TEXT);";
    rc = sqlite3_exec(db, sql, 0, 0, &err_msg);
    if (rc != SQLITE_OK) {
        fprintf(stderr, "Erreur SQL: %s\n", err_msg);
        sqlite3_free(err_msg);
    }
    
    // Fermeture de la base
    sqlite3_close(db);
    return 0;
}
```

### Gestion des erreurs

SQLite utilise des codes de retour numériques :
- `SQLITE_OK` (0) : Succès
- `SQLITE_ERROR` (1) : Erreur SQL générique
- `SQLITE_BUSY` (5) : Base verrouillée
- `SQLITE_CORRUPT` (11) : Base corrompue

Utilisez `sqlite3_errmsg()` pour obtenir un message d'erreur lisible.

### Transactions

SQLite supporte les transactions ACID :

```sql
BEGIN TRANSACTION;
-- Vos requêtes ici
INSERT INTO table1 VALUES (...);
UPDATE table2 SET ... WHERE ...;
COMMIT; -- ou ROLLBACK en cas d'erreur
```

En C, vous pouvez exécuter ces commandes comme n'importe quelle autre requête SQL.

## Fonctionnalités avancées

### Types de données

SQLite utilise un typage dynamique avec cinq types de stockage :
- **NULL** : Valeur nulle
- **INTEGER** : Entier signé (1, 2, 3, 4, 6 ou 8 octets)
- **REAL** : Nombre à virgule flottante (8 octets IEEE 754)
- **TEXT** : Chaîne de caractères (UTF-8, UTF-16BE ou UTF-16LE)
- **BLOB** : Données binaires

### Affinité de type

Contrairement à d'autres SGBD, SQLite n'impose pas strictement les contraintes de type. L'affinité de type détermine comment SQLite convertit les données lors de l'insertion.

### Index et optimisation

Créez des index pour améliorer les performances des requêtes :
```sql
CREATE INDEX idx_nom ON contacts(nom);
```

Vous pouvez également créer des index sur des expressions :
```sql
CREATE INDEX idx_nom_maj ON contacts(UPPER(nom));
```

### Extensions

SQLite supporte plusieurs extensions puissantes :

#### Recherche plein texte (FTS)
```sql
CREATE VIRTUAL TABLE documents USING fts5(title, content);
INSERT INTO documents VALUES ('Titre', 'Contenu du document...');
SELECT * FROM documents WHERE documents MATCH 'recherche';
```

#### JSON
```sql
SELECT json_extract('{"nom": "Jean", "age": 30}', '$.nom');
-- Retourne: Jean
```

#### R-Tree (index spatial)
```sql
CREATE VIRTUAL TABLE zones USING rtree(id, xmin, xmax, ymin, ymax);
```

## Bonnes pratiques

### Performance

- **Regroupez les INSERT dans des transactions** : Chaque transaction nécessite des rotations de disque, donc regrouper plusieurs opérations améliore considérablement les performances.
- **Utilisez des paramètres liés** : Préparez une fois, exécutez plusieurs fois avec différentes valeurs.
- **Créez des index appropriés** : Mais évitez les index inutiles qui ralentissent les INSERT/UPDATE/DELETE.

### Sécurité

- **Évitez les injections SQL** : Utilisez toujours des paramètres liés plutôt que la concaténation de chaînes.
- **Validez les entrées utilisateur** : Même avec des paramètres liés, validez les données avant insertion.

### Gestion de la mémoire

- **Libérez toujours les ressources** : Finalisez les instructions préparées et fermez les connexions.
- **Gérez les erreurs de mémoire** : SQLite gère gracieusement les échecs d'allocation mémoire.

## Débogage et maintenance

### Vérification d'intégrité
```sql
PRAGMA integrity_check;  -- Vérification complète (lente)
PRAGMA quick_check;      -- Vérification rapide
```

### Analyse de performance
```sql
EXPLAIN QUERY PLAN SELECT * FROM table WHERE condition;
```

### Maintenance de la base
```sql
VACUUM;  -- Reconstruit la base pour réduire la taille
ANALYZE; -- Met à jour les statistiques pour l'optimiseur
```

## Limites connues

Consultez la page [limits.html](https://www.sqlite.org/limits.html) pour connaître les limites spécifiques de SQLite, notamment :
- Taille maximale de la base de données : 140 téraoctets
- Longueur maximale d'une chaîne : 1 milliard d'octets
- Nombre maximal de colonnes par table : 2000 (configurable)

SQLite est conçu pour être robuste et fiable, mais comprendre ses limites est essentiel pour une utilisation optimale.
