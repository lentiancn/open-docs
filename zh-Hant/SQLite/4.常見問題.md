# SQLite 常見問題

## 一般問題

### SQLite 是什麼？
SQLite 是一個輕量級的嵌入式 SQL 數據庫引擎。與傳統的客戶端-服務器數據庫系統不同，SQLite 直接讀寫磁盤上的數據庫文件，不需要單獨的服務器進程。

### SQLite 適合用於生產環境嗎？
是的，SQLite 被廣泛用於生產環境，包括移動應用、桌面軟件和 Web 應用。它具有高可靠性、ACID 合規性和良好的性能。

### SQLite 的限制有哪些？
- 最大數據庫大小：140TB
- 最大表數：無硬性限制
- 最大行數：理論上無限（實際受數據庫大小限制）
- 最大列數：2000（默認編譯時可配置為最多 32767）
- 最大索引數：每個表最多 64 個索引

主要限制是並發寫入：SQLite 使用數據庫級鎖定，同一時間只能有一個寫操作。

## 安裝和配置

### 如何升級 SQLite 版本？
只需替換舊的二進制文件或庫文件。SQLite 數據庫格式向後兼容，新版本可以讀取舊版本創建的數據庫。

### 如何啟用外鍵約束？
默認情況下外鍵約束是禁用的。可以在連接時執行：
```sql
PRAGMA foreign_keys = ON;
```

或者在編譯時使用 `-DSQLITE_DEFAULT_FOREIGN_KEYS=1` 選項。

### 如何提高 SQLite 性能？
- 使用事務批量處理多個操作
- 啟用 WAL 模式：`PRAGMA journal_mode = WAL;`
- 調整同步設置：`PRAGMA synchronous = NORMAL;`
- 增加緩存大小：`PRAGMA cache_size = N;`（N 為頁面數）
- 為查詢條件創建適當的索引

## 數據類型和 SQL

### SQLite 支持哪些數據類型？
SQLite 使用動態類型系統，但有五種存儲類別：
- NULL
- INTEGER（有符號整數）
- REAL（浮點數）
- TEXT（字符串）
- BLOB（二進制數據）

### 為什麼我的 BOOLEAN 列不工作？
SQLite 沒有專門的 BOOLEAN 類型。通常使用 INTEGER 類型，其中 0 表示 FALSE，非零值表示 TRUE。

### 如何實現自動遞增主鍵？
使用 `INTEGER PRIMARY KEY`：
```sql
CREATE TABLE example (
    id INTEGER PRIMARY KEY,
    name TEXT
);
```
當插入 NULL 值到 id 列時，SQLite 會自動分配下一個可用的整數。

## 並發和鎖定

### 多個進程可以同時訪問同一個 SQLite 數據庫嗎？
可以，多個進程可以同時讀取數據庫。但是寫操作需要獨占鎖，因此同一時間只能有一個寫操作。

### 如何處理「database is locked」錯誤？
這種錯誤通常發生在高並發寫入場景。解決方案包括：
- 減少事務持續時間
- 使用 WAL 模式
- 實現重試邏輯
- 考慮應用架構是否適合 SQLite

## 備份和恢復

### 如何備份 SQLite 數據庫？
最簡單的方法是複製數據庫文件。由於 SQLite 保證 ACID 特性，即使在數據庫正在使用時複製也是安全的。

也可以使用 `.dump` 命令創建 SQL 備份：
```sql
sqlite3 database.db ".dump" > backup.sql
```

### 如何從損壞的數據庫中恢復數據？
如果數據庫損壞，可以嘗試：
```sql
PRAGMA integrity_check;
```
如果報告損壞，可以使用 `.recover` 命令（SQLite 3.35.0+）：
```sql
sqlite3 damaged.db ".recover" | sqlite3 recovered.db
```

## 開發相關

### 如何在程序中使用 SQLite？
大多數編程語言都有 SQLite 綁定：
- C/C++：直接使用 SQLite C API
- Python：內置 sqlite3 模塊
- Java：SQLite JDBC 驅動
- .NET：System.Data.SQLite
- Node.js：sqlite3 或 better-sqlite3 包

### SQLite 與其他數據庫有何不同？
- 無需安裝和配置
- 數據庫存儲在單個文件中
- 零管理開銷
- 適合嵌入式和小型應用
- 不支持用戶管理和網絡訪問控制

這些只是常見問題的一部分。詳細信息請參考官方文檔。
