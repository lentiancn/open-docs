# Часто задаваемые вопросы о Yarn

## Вопросы, связанные с версиями

### Почему пакет yarn в npm все еще на версии 1.x?
Современные версии Yarn не распространяются через npm с 2019 года. Причина в том, что многие люди полагались на `npm install -g yarn` как часть сборки своих образов, и любые критические изменения нарушали бы их развертывания.

В результате команда Yarn решила прекратить использование пакета yarn в npm и использовать его только для выпусков поддержки 1.x. Современный Yarn теперь устанавливается напрямую с веб-сайта через Corepack или `yarn set version`.

### Почему следует обновиться до Yarn Modern?
Хотя Yarn Classic (1.x) остается важной частью экосистемы JavaScript, обновление рекомендуется, когда это возможно:

- **Новые функции**: Помимо классических функций, Modern предлагает плагины для расширения функциональности, такие как changesets, constraints, workspaces и т.д.
- **Эффективность**: Новые стратегии установки значительно уменьшают размер проекта (например, артефакты CRA были уменьшены с 237 МБ до 45 МБ)
- **Расширяемость**: Создавайте свои собственные функции в соответствии со своими спецификациями без ожидания официальной реализации
- **Стабильность**: Исправляет давние проблемы проектирования из Classic
- **Готовность к будущему**: Современная архитектура позволяет более быструю разработку функций

### Насколько сложна миграция с Classic на Modern?
Обычно необходимо решить несколько основных проблем:

1. **Изменение формата конфигурации**: Больше не читает `.npmrc` или `.yarnrc`, вместо этого использует `.yarnrc.yml`
2. **Зависимости сторонних пакетов**: Некоторые пакеты неправильно указывают зависимости, требуя исправлений через `packageExtensions`
3. **Поддержка редактора**: Требуется однократная настройка SDK
4. **Совместимость инструментов**: Такие инструменты, как React Native и Flow, могут потребовать стратегии линковки `node_modules`

Большинство проектов могут завершить миграцию за полдня работы.

## Вопросы использования

### Какие файлы должны быть добавлены в .gitignore?
**При использовании Zero-Installs**:
```
.yarn/*
!.yarn/cache
!.yarn/patches
!.yarn/plugins
!.yarn/releases
!.yarn/sdks
!.yarn/versions
```

**При отсутствии Zero-Installs**:
```
.pnp.*
.yarn/*
!.yarn/patches
!.yarn/plugins
!.yarn/releases
!.yarn/sdks
!.yarn/versions
```

**Пояснение файлов**:
- `.yarn/cache` и `.pnp.*`: Можно безопасно игнорировать, но требуется `yarn install` после переключения веток
- `.yarn/patches`: Содержит файлы патчей, должен быть закоммичен в репозиторий
- `.yarn/plugins` и `.yarn/releases`: Содержит релизы Yarn, рекомендуется коммитить для согласованности команды
- `yarn.lock`: Всегда должен быть закоммичен в репозиторий

### Поддерживает ли Yarn ESM?
Да, Yarn поддерживает ESM.

Yarn поддерживает стратегию установки `node-modules`, идентичную установке npm. Для режима PnP (Plug'n'Play) поддержка ESM доступна начиная с версии 3.1 через Node Loaders.

### Следует ли коммитить файлы блокировки в репозиторий?
**Да, всегда коммитьте их**.

Независимо от того, разрабатываете ли вы автономные приложения или распределенные библиотеки, файлы блокировки должны храниться вместе с исходным кодом проекта. Это обеспечивает:
- Согласованный опыт разработчика для всех участников
- Возможность сборки проекта в будущем
- Предотвращение проблем дрейфа версий зависимостей

Тестирование непрерывной интеграции должно обрабатываться системами CI, а не путем пропуска файлов блокировки.

## Вопросы технической архитектуры

### Управляется ли Yarn Facebook?
Нет. Хотя Yarn изначально был реализован сотрудником Facebook, текущая активная команда разработчиков состоит исключительно из сотрудников компаний, не являющихся основателями. Вклад сотрудников Facebook проходит тот же процесс проверки, что и других участников.

### Что такое registry.yarnpkg.com? Отслеживает ли нас Facebook?
`registry.yarnpkg.com` — это просто запись CNAME, указывающая на реестр npm, без серверной части. Команда Yarn сохраняет это имя хоста по соображениям надежности — если основной источник станет недоступен, можно перенаправить на копию реестра только для чтения.

Yarn собирает базовую клиентскую телеметрию, но никакие HTTP-логи не достигают инфраструктуры проекта Yarn, тем более Facebook.

### Быстрее ли Yarn других менеджеров пакетов?
Производительность относительна и временная. Основные различия Yarn заключаются в приоритетах и основных ценностях:
- Приоритет функциональности рабочих пространств, поскольку монорепозитории обеспечивают значительную ценность
- Значительные инвестиции в Plug'n'Play, поскольку это важно для экосистемы
- Принятие автономных решений на основе дорожной карты проекта

### Почему TypeScript патчится, даже если я не использую Plug'n'Play?
Yarn автоматически применяет патчи поддержки PnP TypeScript к загруженным версиям TypeScript, потому что:

1. **Согласованность**: Обеспечивает согласованное поведение между средами разработки (node_modules) и производства (PnP)
2. **Согласованность кэша**: Предотвращает различия в кэше пакетов, которые могут нарушить неизменяемые установки
3. **Безвредность**: Патч является пустой операцией, если PnP не включен
4. **Вклад сообщества**: Надеемся в конечном итоге объединить этот PR в основную ветку TypeScript

## Лучшие практики

### Общий доступ к скриптам
Имена скриптов, содержащие двоеточия (например, `build:foo`), можно вызывать из любого рабочего пространства. В сочетании с переменной окружения `$INIT_CWD` это позволяет создавать многоразовые скрипты:

```json
{
  "scripts": {
    "g:tsc": "cd $INIT_CWD && tsc"
  }
}
```

Затем вызывайте из любого рабочего пространства, содержащего `tsconfig.json`:
```json
{
  "scripts": {
    "build": "yarn g:tsc"
  }
}
```
