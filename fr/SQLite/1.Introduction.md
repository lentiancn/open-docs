# Introduction à SQLite

SQLite est une bibliothèque en langage C qui implémente un moteur de base de données SQL **petit**, **rapide**, **autonome**, **haute fiabilité** et **complet**.

SQLite est le moteur de base de données le plus utilisé au monde, intégré dans tous les téléphones mobiles et la plupart des ordinateurs, ainsi que dans d'innombrables autres applications utilisées quotidiennement.

## Caractéristiques principales

- **Autonome** : SQLite est une bibliothèque intégrée qui n'a pas besoin d'un processus serveur séparé.
- **Sans serveur** : Contrairement à la plupart des autres bases de données SQL, SQLite ne nécessite pas de processus serveur distinct.
- **Configuration zéro** : Aucune configuration n'est nécessaire pour faire fonctionner SQLite.
- **Transactionnel** : SQLite supporte les transactions ACID (Atomicité, Cohérence, Isolation, Durabilité).
- **Fichier unique** : Une base de données SQLite complète avec plusieurs tables, index, déclencheurs et vues est contenue dans un seul fichier disque.
- **Format de fichier multiplateforme** : Le format de fichier de base de données est compatible entre différentes architectures (32/64 bits, big-endian/little-endian).

## À quoi sert SQLite ?

Pensez à SQLite non pas comme un remplacement pour Oracle, mais comme un remplacement pour `fopen()`. SQLite est particulièrement adapté comme format de fichier d'application, permettant de stocker des données structurées dans un seul fichier facilement portable.

## Taille et performance

SQLite est une bibliothèque compacte. Avec toutes les fonctionnalités activées, la taille de la bibliothèque peut être inférieure à 900 Ko, selon la plateforme cible et les paramètres d'optimisation du compilateur. Malgré sa petite taille, SQLite offre généralement de bonnes performances, même dans des environnements à faible mémoire.

## Fiabilité

SQLite est très soigneusement testé avant chaque version et jouit d'une réputation de grande fiabilité. La majorité du code source de SQLite est consacrée purement aux tests et à la vérification. Une suite de tests automatisée exécute des millions de cas de test impliquant des centaines de millions d'instructions SQL individuelles et atteint une couverture de test de 100% des branches.

Les transactions sont ACID même si elles sont interrompues par des pannes système ou des coupures de courant.
