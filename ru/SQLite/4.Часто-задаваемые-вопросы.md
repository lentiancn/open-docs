# Часто задаваемые вопросы по SQLite

## (1) Как создать поле с автоинкрементом?

Краткий ответ: Столбец, объявленный как **INTEGER PRIMARY KEY**, будет автоинкрементироваться.

Подробный ответ: Если вы объявите столбец таблицы как **INTEGER PRIMARY KEY**, то при вставке NULL в этот столбец, NULL автоматически преобразуется в целое число, которое на единицу больше максимального значения этого столбца среди всех других строк таблицы, или 1, если таблица пуста.

Функция **sqlite3_last_insert_rowid()** возвращает целочисленный ключ для последней операции вставки.

Если вы хотите, чтобы ключи были уникальными за всё время существования таблицы (включая удаленные записи), добавьте ключевое слово **AUTOINCREMENT** к объявлению INTEGER PRIMARY KEY.

## (2) Какие типы данных поддерживает SQLite?

SQLite использует **динамическую типизацию**. Содержимое может храниться как INTEGER, REAL, TEXT, BLOB или как NULL.

## (3) SQLite позволяет мне вставлять строку в столбец базы данных типа integer!

Это особенность, а не ошибка. SQLite использует **динамическую типизацию** и не применяет ограничения типов данных. Данные любого типа могут быть вставлены в любой столбец.

Однако SQLite использует объявленный тип столбца как подсказку о предпочитаемом формате значений. Например, если столбец имеет тип INTEGER и вы пытаетесь вставить строку, SQLite попытается преобразовать строку в целое число. Эта функция называется **аффинностью типов**.

## (4) Почему SQLite не позволяет использовать '0' и '0.0' в качестве первичного ключа для двух разных строк одной таблицы?

Эта проблема возникает, когда ваш первичный ключ имеет числовой тип. Измените тип данных вашего первичного ключа на TEXT.

Для столбца с числовым типом SQLite считает '0' и '0.0' одинаковыми значениями, поскольку они численно равны друг другу.

## (5) Могут ли несколько приложений или несколько экземпляров одного приложения одновременно обращаться к одному файлу базы данных?

Несколько процессов могут одновременно открывать одну и ту же базу данных. Несколько процессов могут одновременно выполнять SELECT. Однако только один процесс может вносить изменения в базу данных в любой момент времени.

SQLite использует блокировки чтения/записи для контроля доступа к базе данных. Будьте осторожны: этот механизм блокировки может не работать корректно, если файл базы данных находится в файловой системе NFS.

## (6) Является ли SQLite потокобезопасным?

SQLite является потокобезопасным. Однако для этого SQLite должен быть скомпилирован с макроопределением препроцессора SQLITE_THREADSAFE, установленным в 1. Предварительно скомпилированные двоичные файлы для Windows и Linux скомпилированы именно так.

Вы можете вызвать интерфейс **sqlite3_threadsafe()**, чтобы узнать, скомпилирована ли библиотека SQLite как потокобезопасная.

## (7) Как получить список всех таблиц/индексов в базе данных SQLite?

Если вы используете программу командной строки sqlite3, введите **".tables"** для получения списка всех таблиц или **".schema"** для просмотра полной схемы базы данных.

Из программы на C/C++ можно выполнить SELECT к специальной таблице **"sqlite_schema"**:

```sql
SELECT name FROM sqlite_schema WHERE type='table' ORDER BY name;
```

## (8) Существуют ли известные ограничения размера баз данных SQLite?

См. документ **limits.html** для полного обсуждения ограничений SQLite.

## (9) Каков максимальный размер VARCHAR в SQLite?

SQLite не применяет ограничение длины VARCHAR. Вы можете объявить VARCHAR(10), и SQLite будет рад хранить там строку из 500 миллионов символов. Ваше содержимое никогда не будет усечено. SQLite понимает тип столбца "VARCHAR(N)" как "TEXT", независимо от значения N.

## (10) Поддерживает ли SQLite тип BLOB?

SQLite позволяет хранить данные BLOB в любом столбце, даже в столбцах, объявленных для хранения другого типа. BLOB даже могут использоваться в качестве PRIMARY KEY.

## (11) Как добавить, удалить или переименовать столбцы существующей таблицы в SQLite?

SQLite имеет ограниченную поддержку ALTER TABLE, которую можно использовать для добавления, переименования или удаления столбцов, а также для изменения имени таблицы.

Если вам нужно внести более сложные изменения в структуру таблицы, вам придется пересоздать ее. Вы можете сохранить существующие данные во временную таблицу, удалить старую таблицу, создать новую таблицу, а затем скопировать данные обратно из временной таблицы.

## (12) Я удалил много данных, но файл базы данных не стал меньше. Это ошибка?

Нет. Когда вы удаляете информацию из базы данных SQLite, неиспользуемое дисковое пространство добавляется во внутренний "список свободных блоков" и повторно используется при следующей вставке данных.

Если вы удалили много данных и хотите уменьшить файл базы данных, выполните команду **VACUUM**. VACUUM перестроит базу данных с нуля, оставив минимальный по размеру файл.

Альтернатива — режим авто-VACUUM, включаемый с помощью прагмы **auto_vacuum**.

## (13) Могу ли я использовать SQLite в своем коммерческом продукте без выплаты роялти?

Да. SQLite находится в **общественном достоянии**. Никаких прав собственности не заявляется ни на какую часть кода. Вы можете делать с ним всё, что хотите.

## (14) Как использовать строковый литерал, содержащий встроенный одинарный кавычка (')?

Согласно стандарту SQL, одинарные кавычки в строках экранируются путем удвоения одинарных кавычек. Пример:

```sql
INSERT INTO xyz VALUES('5 O''clock');
```

## (15) Что такое ошибка SQLITE_SCHEMA и почему я получаю её?

Ошибка **SQLITE_SCHEMA** возвращается, когда подготовленный SQL-оператор больше не действителен и не может быть выполнен. В этом случае оператор должен быть перекомпилирован из SQL с использованием API **sqlite3_prepare()**.

Самый простой способ справиться с ошибками SQLITE_SCHEMA — всегда использовать **sqlite3_prepare_v2()** вместо **sqlite3_prepare()**.

## (17) При компиляции SQLite я получаю некоторые предупреждения компилятора. Разве это не проблема? Не указывает ли это на плохое качество кода?

Обеспечение качества в SQLite осуществляется с помощью **полного покрытия тестированием**, а не с помощью предупреждений компилятора или других инструментов статического анализа кода. Большая часть кодовой базы SQLite посвящена исключительно тестированию.

## (18) Сравнение без учета регистра для Unicode-символов не работает.

Конфигурация SQLite по умолчанию поддерживает сравнение без учета регистра только для ASCII-символов. Полная поддержка Unicode потребовала бы таблиц и логики, которые почти удвоили бы размер библиотеки SQLite.

Вместо предоставления полной поддержки Unicode по умолчанию, SQLite предоставляет возможность связываться с внешними процедурами сравнения и преобразования Unicode. Приложение может перегрузить встроенную последовательность сравнения **NOCASE** и встроенные функции **like()**, **upper()**, **lower()**.

## (19) INSERT очень медленный — я могу выполнить всего несколько десятков INSERT в секунду

На самом деле SQLite легко выполняет 50 000 или более операторов INSERT в секунду на среднем настольном компьютере. Но он выполняет всего несколько десятков транзакций в секунду. Скорость транзакций ограничена скоростью вращения жесткого диска.

По умолчанию каждый оператор INSERT является своей собственной транзакцией. Но если вы окружите несколько операторов INSERT командами **BEGIN...COMMIT**, все вставки будут сгруппированы в одну транзакцию, что значительно повысит производительность.

Другой вариант — выполнить **PRAGMA synchronous=OFF**. Это заставит SQLite не ждать, пока данные действительно достигнут поверхности диска, что сделает операции записи намного быстрее. Но если питание пропадет в середине транзакции, файл базы данных может повредиться.

## (20) Я случайно удалил важную информацию из своей базы данных SQLite. Как я могу восстановить её?

Если у вас есть резервная копия файла базы данных, восстановите информацию из резервной копии.

Если у вас нет резервной копии, восстановление очень затруднительно. Возможно, вам удастся найти частичные строковые данные в двоичном дампе необработанного файла базы данных.

## (21) Что такое ошибка SQLITE_CORRUPT? Что означает, что база данных "повреждена"? Почему я получаю эту ошибку?

Ошибка **SQLITE_CORRUPT** возвращается, когда SQLite обнаруживает ошибку в структуре, формате или других управляющих элементах файла базы данных.

SQLite не повреждает файлы базы данных без внешней помощи. Если ваше приложение аварийно завершится во время обновления, ваши данные будут в безопасности. База данных безопасна даже при сбое ОС или отключении питания.

Однако существуют вещи, которые внешние программы или ошибки в вашем оборудовании или ОС могут сделать для повреждения файла базы данных. См. документ **"How To Corrupt An SQLite Database File"** для получения дополнительной информации.

## (22) Поддерживает ли SQLite внешние ключи?

Начиная с версии **3.6.19** (2009-10-14), SQLite поддерживает ограничения внешних ключей. Однако применение ограничений внешних ключей отключено по умолчанию (для обратной совместимости).

Чтобы включить применение ограничений внешних ключей, выполните **PRAGMA foreign_keys=ON** или скомпилируйте с **-DSQLITE_DEFAULT_FOREIGN_KEYS=1**.

## (24) Мое выражение в предложении WHERE column1="column1" не работает. Оно возвращает все строки таблицы, а не только те строки, где column1 имеет значение "column1".

Используйте одинарные кавычки, а не двойные, вокруг строковых литералов в SQL. Это требование стандарта SQL. Ваше выражение в предложении WHERE должно читаться: **column1='column1'**.

SQL использует двойные кавычки вокруг идентификаторов (имен столбцов или таблиц), которые содержат специальные символы или являются ключевыми словами. Поэтому когда вы пишете column1="column1", это эквивалентно column1=column1, что, очевидно, всегда истинно.

## (28) Мой запрос не возвращает имя столбца, которое я ожидаю. Это ошибка?

Если столбцы результирующего набора именуются предложениями AS, то SQLite гарантирует использование идентификатора справа от ключевого слова AS в качестве имени столбца. Если результирующий набор не использует предложение AS, то SQLite может назвать столбец так, как ему удобно.

## (29) Куда делась моя база данных? (Или: Как моя база данных стала пустой?)

Если не указаны флаги, предотвращающие это, база данных SQLite создается, если она еще не существует. Недавно созданные базы данных изначально пусты. Это может сбивать с толку людей, которые случайно открывают разные файлы базы данных в разных контекстах из-за опечатки в имени файла или использования относительного пути, который используется с разными текущими каталогами для открывающих процессов.
