# Oracle Database よくある質問

## インストール関連の質問

### Q1: インストール中に権限エラーが発生した場合はどうすればよいですか？
**A**: oracle ユーザーでインストールを実行し、そのユーザーが oinstall および dba グループに属していることを確認してください。`/etc/passwd` および `/etc/group` ファイルでユーザーとグループの設定を確認します。

### Q2: インストール時にメモリ不足のエラーが発生した場合はどうすればよいですか？
**A**: Oracle Database には十分なメモリが必要です。以下の対応が可能です：
- システムの物理メモリを増加させる
- カーネルパラメータ `kernel.shmmax` および `kernel.shmall` を調整する
- インストール時に小さい構成オプション（デスクトップクラスインストールなど）を選択する

### Q3: Docker で Oracle Database を実行するにはどうすればよいですか？
**A**: Oracle は公式 Docker イメージを提供しています：
```bash
# Oracle Database Free (19c)
docker pull container-registry.oracle.com/database/free:19.3.0.0
docker run -d -p 1521:1521 --name oracle-free container-registry.oracle.com/database/free:19.3.0.0

# 注記：初回起動には初期化に時間がかかる場合があります
```

## 接続の問題

### Q4: ORA-12541: TNS:no listener エラーを解決するにはどうすればよいですか？
**A**: このエラーはリスナーが実行されていないことを示しています。以下の対応を行ってください：
```bash
# リスナーの起動
lsnrctl start

# リスナーのステータス確認
lsnrctl status

# リスナー設定の確認（listener.ora ファイル）
```

### Q5: ORA-12170: TNS:Connect timeout occurred エラーが発生する場合は？
**A**: ネットワーク接続タイムアウトです。以下の点を確認してください：
- データベースサーバーへの到達可能性（ping テスト）
- ファイアウォールがポート 1521 をブロックしていないか
- リスナーが正しい IP アドレスでリッスンしているか
- tnsnames.ora 設定の正確性

### Q6: sys/system パスワードをリセットするにはどうすればよいですか？
**A**: orapwd ツールを使用してパスワードファイルをリセットします：
```bash
# データベースの停止
sqlplus / as sysdba
SHUTDOWN IMMEDIATE;

# パスワードファイルの再作成
orapwd file=$ORACLE_HOME/dbs/orapw$ORACLE_SID password=new_password force=y

# データベースの起動
STARTUP;
```

## パフォーマンスの問題

### Q7: クエリが遅い場合の最適化方法は？
**A**: パフォーマンス最適化の手順：
1. **実行計画の分析**：`EXPLAIN PLAN` を使用してクエリ実行パスを確認
2. **インデックスの確認**：WHERE 句の列に適切なインデックスがあるか確認
3. **統計情報の収集**：`EXEC DBMS_STATS.GATHER_TABLE_STATS`
4. **SQL チューニングアドバイザー**：Oracle SQL Tuning Advisor の使用
5. **待機イベントの確認**：`v$session_wait` ビューの照会

### Q8: 現在実行中の遅いクエリを確認するには？
**A**: v$session および v$sql ビューを照会します：
```sql
SELECT s.sid, s.serial#, s.username, s.status, 
       q.sql_text, q.elapsed_time, q.cpu_time
FROM v$session s, v$sql q
WHERE s.sql_id = q.sql_id
  AND s.status = 'ACTIVE'
  AND q.elapsed_time > 1000000; -- 実行時間が1秒を超える場合
```

### Q9: メモリ使用量が高すぎる場合はどうすればよいですか？
**A**: メモリパラメータを調整します：
- **SGA_TARGET**: システムグローバルエリアの合計サイズ
- **PGA_AGGREGATE_TARGET**: プログラムグローバルエリアの合計サイズ
- **MEMORY_TARGET**: 自動メモリ管理（11g 以降）

```sql
-- 現在のメモリ使用状況の確認
SHOW PARAMETER memory;
SHOW PARAMETER sga;
SHOW PARAMETER pga;

-- 動的調整（sysdba 権限が必要）
ALTER SYSTEM SET MEMORY_TARGET = 4G SCOPE=BOTH;
```

## バックアップとリカバリの問題

### Q10: RMAN バックアップが失敗した場合はどうすればよいですか？
**A**: 一般的な RMAN のトラブルシューティング：
- **空き容量不足**：バックアップ先ディレクトリの空き容量を確認
- **権限の問題**：oracle ユーザーがバックアップディレクトリに書き込み権限を持っているか確認
- **アーカイブログの欠落**：すべてのアーカイブログが利用可能であることを確認
- **チャネル設定**：RMAN チャネル設定が正しいか確認

### Q11: 誤って削除したテーブルを復元するには？
**A**: 復元方法はバックアップ戦略によって異なります：
1. **フラッシュバックテーブル**（有効な場合）：
   ```sql
   FLASHBACK TABLE table_name TO BEFORE DROP;
   ```
2. **RMAN ポイントインタイムリカバリ**：
   ```rman
   RUN {
       SET UNTIL TIME "TO_DATE('2026-03-30 08:00:00', 'YYYY-MM-DD HH24:MI:SS')";
       RESTORE DATABASE;
       RECOVER DATABASE;
   }
   ```
3. **Data Pump インポート**：最新のエクスポートファイルから復元

## バージョンの違い

### Q12: Oracle Database 19c と 26ai の主な違いは何ですか？
**A**: 主な違いは以下の通りです：
- **AI 機能**：26ai は AI ドリブンの自動化管理機能を統合
- **パフォーマンス最適化**：26ai はよりスマートなリソース管理とクエリ最適化を提供
- **セキュリティ**：26ai はセキュリティ監視と脅威検出機能を強化
- **クラウドネイティブサポート**：26ai はコンテナ化とクラウド環境へのサポートが向上

### Q13: 19c から 26ai へのアップグレードで注意すべき点は？
**A**: アップグレード時の考慮事項：
- **互換性チェック**：Database Upgrade Assistant (DBUA) を使用して事前チェックを実施
- **バックアップ**：アップグレード前に必ずデータベースを完全バックアップ
- **テスト環境**：まずテスト環境でアップグレードプロセスを検証
- **アプリケーション互換性**：アプリケーションが新バージョンと互換性があることを確認
- **ライセンス**：新バージョンのライセンス要件を確認

## 日常的なメンテナンス

### Q14: アーカイブログをクリーンアップするには？
**A**: アーカイブログのクリーンアップ方法：
```bash
# RMAN を使用してバックアップ済みのアーカイブログを削除
rman target /
DELETE ARCHIVELOG ALL COMPLETED BEFORE 'SYSDATE-7';

# 手動削除（バックアップ済みであることが確実な場合のみ推奨）
rm $ORACLE_BASE/fast_recovery_area/*/archivelog/*.arc
```

### Q15: 表領域がいっぱいになった場合は？
**A**: 表領域の拡張方法：
```sql
-- データファイルの追加
ALTER TABLESPACE users ADD DATAFILE '/u01/app/oracle/oradata/ORCL/users02.dbf' SIZE 1G;

-- 既存データファイルのサイズ変更
ALTER DATABASE DATAFILE '/u01/app/oracle/oradata/ORCL/users01.dbf' RESIZE 2G;

-- 自動拡張の有効化
ALTER DATABASE DATAFILE '/u01/app/oracle/oradata/ORCL/users01.dbf' AUTOEXTEND ON NEXT 100M MAXSIZE UNLIMITED;
```

### Q16: データベースの健全状態を監視するには？
**A**: 健全状態監視の方法：
- **AWR レポート**：定期的に AWR レポートを生成・分析
- **ADDM レポート**：自動データベース診断モニター
- **OEM**：Oracle Enterprise Manager
- **カスタムスクリプト**：重要なメトリクス（セッション数、ロック、表領域使用率など）を監視

## トラブルシューティング

### Q17: データベースが起動できない場合は？
**A**: 起動トラブルシューティングの手順：
1. **alert log の確認**：`$ORACLE_BASE/diag/rdbms/<DB_NAME>/trace/alert_<SID>.log`
2. **制御ファイルの確認**：制御ファイルが存在し、アクセス可能であることを確認
3. **データファイルの確認**：すべてのデータファイルが存在することを確認
4. **パラメータファイルの確認**：spfile または pfile の設定が正しいか確認
5. **マウントモードの試行**：`STARTUP MOUNT` してから段階的にトラブルシューティング

### Q18: デッドロックが発生した場合は？
**A**: デッドロックの処理方法：
- **自動処理**：Oracle は自動的に検出し、いずれかのトランザクションを終了
- **手動介入**：`v$lock` および `v$session` を照会してブロッキングセッションを特定し kill
  ```sql
  ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE;
  ```
- **予防策**：アプリケーションレベルで一貫したアクセス順序を確保

## ライセンスとコスト

### Q19: Oracle Database の無料版にはどのような制限がありますか？
**A**: Oracle Database Free (19c/26ai) の制限：
- **CPU 制限**：最大 2 CPU
- **メモリ制限**：最大 2GB RAM
- **ストレージ制限**：最大 12GB のユーザーデータ
- **機能制限**：エンタープライズエディションの高度な機能（RAC、Data Guard など）を含まない

### Q20: Oracle ライセンスコストを削減するには？
**A**: コスト最適化戦略：
- **無料版の使用**：開発および小規模な本番環境向け
- **CPU ライセンスの適切な計画**：実際の使用状況に基づいて購入
- **クラウドサービスの検討**：OCI、AWS RDS などの従量課金モデル
- **定期的な監査**：ライセンスのコンプライアンスを確保し、過剰使用を回避
