# Oracle Database 常見問題

## 安裝相關問題

### Q1: 安裝過程中出現權限錯誤怎麼辦？
**A**: 確保使用 oracle 使用者執行安裝，並且該使用者屬於 oinstall 和 dba 群組。檢查 `/etc/passwd` 和 `/etc/group` 檔案確認使用者和群組設定正確。

### Q2: 安裝時提示記憶體不足如何解決？
**A**: Oracle Database 需要足夠的記憶體。可以：
- 增加系統實體記憶體
- 調整核心參數：`kernel.shmmax` 和 `kernel.shmall`
- 在安裝時選擇較小的設定選項（如桌面類安裝）

### Q3: 如何在 Docker 中執行 Oracle Database？
**A**: Oracle 提供官方 Docker 映像檔：
```bash
# Oracle Database Free (19c)
docker pull container-registry.oracle.com/database/free:19.3.0.0
docker run -d -p 1521:1521 --name oracle-free container-registry.oracle.com/database/free:19.3.0.0

# 注意：首次啟動可能需要較長時間初始化
```

## 連接問題

### Q4: ORA-12541: TNS:no listener 錯誤如何解決？
**A**: 此錯誤表示監聽器未執行。解決方案：
```bash
# 啟動監聽器
lsnrctl start

# 檢查監聽器狀態
lsnrctl status

# 確保監聽器設定正確（listener.ora 檔案）
```

### Q5: ORA-12170: TNS:Connect timeout occurred 錯誤？
**A**: 網路連接逾時，檢查：
- 資料庫伺服器是否可達（ping 測試）
- 防火牆是否阻止 1521 連接埠
- 監聽器是否在正確的 IP 位址上監聽
- tnsnames.ora 設定是否正確

### Q6: 如何重設 sys/system 密碼？
**A**: 使用 orapwd 工具重設密碼檔案：
```bash
# 停止資料庫
sqlplus / as sysdba
SHUTDOWN IMMEDIATE;

# 重新建立密碼檔案
orapwd file=$ORACLE_HOME/dbs/orapw$ORACLE_SID password=new_password force=y

# 啟動資料庫
STARTUP;
```

## 效能問題

### Q7: 查詢很慢如何最佳化？
**A**: 效能最佳化步驟：
1. **分析執行計畫**：使用 `EXPLAIN PLAN` 檢視查詢執行路徑
2. **檢查索引**：確保 WHERE 子句中的欄位有適當索引
3. **收集統計資訊**：`EXEC DBMS_STATS.GATHER_TABLE_STATS`
4. **SQL 調校顧問**：使用 Oracle SQL Tuning Advisor
5. **檢查等待事件**：查詢 `v$session_wait` 檢視

### Q8: 如何檢視目前正在執行的慢查詢？
**A**: 查詢 v$session 和 v$sql 檢視：
```sql
SELECT s.sid, s.serial#, s.username, s.status, 
       q.sql_text, q.elapsed_time, q.cpu_time
FROM v$session s, v$sql q
WHERE s.sql_id = q.sql_id
  AND s.status = 'ACTIVE'
  AND q.elapsed_time > 1000000; -- 執行時間超過1秒
```

### Q9: 記憶體使用過高怎麼辦？
**A**: 調整記憶體參數：
- **SGA_TARGET**: 系統全域區總大小
- **PGA_AGGREGATE_TARGET**: 程式全域區總大小
- **MEMORY_TARGET**: 自動記憶體管理（11g 及以上）

```sql
-- 檢視目前記憶體使用
SHOW PARAMETER memory;
SHOW PARAMETER sga;
SHOW PARAMETER pga;

-- 動態調整（需要 sysdba 權限）
ALTER SYSTEM SET MEMORY_TARGET = 4G SCOPE=BOTH;
```

## 備份還原問題

### Q10: RMAN 備份失敗如何處理？
**A**: 常見 RMAN 問題排查：
- **空間不足**：檢查備份目標目錄空間
- **權限問題**：確保 oracle 使用者對備份目錄有寫入權限
- **歸檔日誌遺失**：確保所有歸檔日誌都可用
- **通道設定**：檢查 RMAN 通道設定是否正確

### Q11: 如何還原誤刪除的資料表？
**A**: 還原方法取決於備份策略：
1. **閃回資料表**（如果啟用）：
   ```sql
   FLASHBACK TABLE table_name TO BEFORE DROP;
   ```
2. **RMAN 時間點還原**：
   ```rman
   RUN {
       SET UNTIL TIME "TO_DATE('2026-03-30 08:00:00', 'YYYY-MM-DD HH24:MI:SS')";
       RESTORE DATABASE;
       RECOVER DATABASE;
   }
   ```
3. **Data Pump 匯入**：從最近的匯出檔案還原

## 版本差異問題

### Q12: Oracle Database 19c 和 26ai 有什麼主要區別？
**A**: 主要區別包括：
- **AI 功能**：26ai 整合了 AI 驅動的自動化管理功能
- **效能最佳化**：26ai 提供更智慧的資源管理和查詢最佳化
- **安全性**：26ai 增強了安全監控和威脅偵測能力
- **雲原生支援**：26ai 對容器化和雲環境有更好的支援

### Q13: 從 19c 升級到 26ai 需要注意什麼？
**A**: 升級注意事項：
- **相容性檢查**：使用 Database Upgrade Assistant (DBUA) 進行預先檢查
- **備份**：升級前必須完整備份資料庫
- **測試環境**：先在測試環境驗證升級過程
- **應用程式相容性**：確保應用程式與新版本相容
- **授權**：確認新版本的授權要求

## 日常維護

### Q14: 如何清理歸檔日誌？
**A**: 歸檔日誌清理方法：
```bash
# 使用 RMAN 刪除已備份的歸檔日誌
rman target /
DELETE ARCHIVELOG ALL COMPLETED BEFORE 'SYSDATE-7';

# 手動刪除（不建議，除非確定已備份）
rm $ORACLE_BASE/fast_recovery_area/*/archivelog/*.arc
```

### Q15: 資料表空間滿了怎麼辦？
**A**: 資料表空間擴充方法：
```sql
-- 增加資料檔
ALTER TABLESPACE users ADD DATAFILE '/u01/app/oracle/oradata/ORCL/users02.dbf' SIZE 1G;

-- 擴充現有資料檔
ALTER DATABASE DATAFILE '/u01/app/oracle/oradata/ORCL/users01.dbf' RESIZE 2G;

-- 啟用自動擴充
ALTER DATABASE DATAFILE '/u01/app/oracle/oradata/ORCL/users01.dbf' AUTOEXTEND ON NEXT 100M MAXSIZE UNLIMITED;
```

### Q16: 如何監控資料庫健康狀態？
**A**: 健康監控方法：
- **AWR 報告**：定期產生和分析 AWR 報告
- **ADDM 報告**：自動資料庫診斷監視器
- **OEM**：Oracle Enterprise Manager
- **自訂腳本**：監控關鍵指標（工作階段數、鎖定、資料表空間使用率等）

## 故障排除

### Q17: 資料庫無法啟動怎麼辦？
**A**: 啟動故障排查步驟：
1. **檢查 alert log**：`$ORACLE_BASE/diag/rdbms/<DB_NAME>/trace/alert_<SID>.log`
2. **檢查控制檔**：確保控制檔存在且可存取
3. **檢查資料檔**：確保所有資料檔存在
4. **檢查參數檔案**：spfile 或 pfile 設定是否正確
5. **嘗試 mount 模式**：`STARTUP MOUNT` 然後逐步排查

### Q18: 出現死結如何處理？
**A**: 死結處理方法：
- **自動處理**：Oracle 會自動偵測並終止其中一個交易
- **手動介入**：查詢 `v$lock` 和 `v$session` 找到阻塞工作階段並 kill
  ```sql
  ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE;
  ```
- **預防措施**：應用程式層面確保一致的存取順序

## 授權和成本

### Q19: Oracle Database 免費版本有哪些限制？
**A**: Oracle Database Free (19c/26ai) 限制：
- **CPU 限制**：最多 2 個 CPU
- **記憶體限制**：最多 2GB RAM
- **儲存限制**：最多 12GB 使用者資料
- **功能限制**：不包含企業版進階功能（如 RAC、Data Guard 等）

### Q20: 如何降低 Oracle 授權成本？
**A**: 成本最佳化策略：
- **使用免費版本**：對於開發和小型生產環境
- **合理規劃 CPU 授權**：根據實際使用情況購買
- **考慮雲端服務**：OCI、AWS RDS 等按需付費模式
- **定期稽核**：確保授權合規，避免超額使用
