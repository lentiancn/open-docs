# Preguntas Frecuentes de Yarn

## Preguntas Relacionadas con la Instalación

### P: ¿Cómo elegir entre las versiones de Yarn?
**R**: 
- **Nuevos Proyectos**: Se recomienda usar Yarn v4+ para disfrutar de características modernas y mejor rendimiento
- **Proyectos Existentes**: Si ya usa Yarn v1, puede continuar usándolo o considerar migrar a la versión moderna
- **Entornos Empresariales**: Yarn v1 proporciona un soporte a largo plazo más estable, mientras que v4+ ofrece características más innovadoras

### P: ¿Qué es Corepack y por qué lo necesito?
**R**: Corepack es una herramienta intermedia incluida con Node.js que le permite configurar la versión del gestor de paquetes por proyecto. Asegura que los miembros del equipo usen la misma versión de Yarn, evitando problemas de inconsistencia de versiones.

### P: ¿Qué hacer si encuentro errores de permisos durante la instalación de Yarn?
**R**: 
- Añada la bandera `--unsafe-perm` cuando use `npm install --global yarn`
- Use nvm para gestionar versiones de Node.js
- En entornos CI/CD, normalmente no se requiere instalación global

## Preguntas Relacionadas con el Uso

### P: ¿Cuáles son las diferencias entre Yarn y npm?
**R**: 
- **Velocidad**: Yarn usa instalaciones paralelas y caché fuera de línea, normalmente más rápido
- **Determinismo**: Yarn garantiza instalaciones consistentes (yarn.lock)
- **Características**: Yarn proporciona workspaces, PnP, sistema de plugins y otras características avanzadas
- **Comandos**: Yarn reimplementa todos los comandos para una mejor experiencia del desarrollador

### P: ¿Qué es PnP (Plug'n'Play)?
**R**: PnP es una característica de Yarn v2+ que elimina el directorio node_modules resolviendo las dependencias directamente desde la caché. Esto ahorra espacio en disco y mejora la velocidad de instalación, pero puede ser incompatible con algunas herramientas que no soportan PnP.

### P: ¿Cómo usar workspaces en mi proyecto?
**R**: 
1. Añada un campo `"workspaces"` a su `package.json` raíz
2. Cree directorios de sub-paquetes (por ejemplo, `packages/`)
3. Cree archivos `package.json` individuales en sub-paquetes
4. Use `yarn workspace <name> <command>` para ejecutar comandos en workspaces específicos

### P: ¿Cuáles son las ventajas de Yarn PnP?
**R**: Yarn PnP proporciona varias ventajas clave:
- **Huella de instalación mínima**: Sin copia de archivos, solo genera un archivo de cargador
- **Instalaciones compartidas entre discos**: Reutiliza los artefactos de paquetes en todos los proyectos  
- **Hoisting perfecto**: Elimina las dependencias fantasma completamente
- **Protección contra dependencias fantasma**: Previene el acceso a dependencias no declaradas
- **Semantic erroring**: Proporciona mensajes de error claros y accionables en lugar de errores genéricos "Cannot find module"

## Preguntas sobre Migración de Versiones

### P: ¿Cómo migrar de Yarn v1 a v4+?
**R**: 
1. Asegúrese de que su proyecto esté bajo control de versiones Git
2. Ejecute `yarn set version stable` (para v4+) 
3. Siga la guía de migración para actualizar las configurations paso a paso
4. Testee toda la funcionalidad para asegurar la compatibilidad

### P: ¿Qué hacer si encuentro problemas de compatibilidad después de la migración?
**R**: 
- Verifique si alguna herramienta no soporta PnP, puede deshabilitar PnP: `yarn config set nodeLinker node-modules`
-_actualice las dependencias a versiones compatibles
- Use `packageExtensions` en `.yarnrc.yml` para corregir dependencias fantasma
- Consulte la documentación oficial de migración para soluciones específicas

### P: ¿Puedo mantener el uso de node_modules en lugar de PnP?
**R**: ¡Sí! Puede revertir a instalaciones tradicionales de node_modules en cualquier momento añadiendo esto a su `.yarnrc.yml`:

```yaml
nodeLinker: node-modules
```

Esto le da todos los beneficios de Yarn moderno (workspaces, plugins, etc.) mientras mantiene la compatibilidad con herramientas que requieren node_modules.

##Solución de Problemas

### P: ¿Qué hacer si `yarn install` falla?
**R**: 
- Limpiar caché: `yarn cache clean`
- Eliminar `yarn.lock` y reinstalar
- Verificar la conexión de red y la configuración del registro
- Para Yarn v4+, verificar la configuración de `.yarnrc.yml`

### P: ¿Cómo verificar la versión de Yarn?
**R**: 
- Versión global: `yarn --version`
- Versión del proyecto: Comprobar el directorio `.yarn/releases/` o el archivo `.yarnrc.yml`

### P: ¿Qué hacer si los comandos de Yarn son muy lentos?
**R**: 
- Asegurarse de que la caché fuera de línea esté habilitada
- Verificar la conexión de red
- Para proyectos grandes, considerar usar workspaces para dividir la base de código
- Actualizar a la última versión para mejorar el rendimiento

### P: ¿Cómo corregir errores de "dependencia fantasma" en PnP?
**R**: Las dependencias fantasma ocurren cuando el código intenta acceder a paquetes que no están declarados en sus dependencias. Corríjalos usando `packageExtensions` en su `.yarnrc.yml`:

```yaml
packageExtensions:
  "@babel/core@*":
    dependencies:
      "@babel/types": "*"
```

Esto le dice a Yarn que `@babel/core` debería tener acceso a `@babel/types`, incluso si no está declarado explícitamente.

## Uso Avanzado

### P: ¿Cómo usar Yarn con React Native?
**R**: React Native requiere instalaciones tradicionales de node_modules. Deshabilite PnP estableciendo:

```yaml
nodeLinker: node-modules
```

en su archivo `.yarnrc.yml`.

### P: ¿Cómo compartir binarios entre workspaces?
**R**: Cuando use PnP, los binarios solo están disponibles en el workspace que los declara. Para compartir herramientas como TypeScript entre workspaces:

1. Crear un workspace de "tooling" que contenga sus herramientas de infraestructura
2. Hacer que todos los otros workspaces dependan del workspace de tooling
3. O declarar las herramientas como dependencias en cada workspace que las necesite

### P: ¿Qué protocolos soporta Yarn?
**R**: Yarn soporta múltiples protocolos para fuentes de paquetes:
- **npm**: Paquetes del registro npm estándar
- **file**: Paquetes locales (`file:../path/to/package`)
- **github**: Repositorios de GitHub (`github:user/repo#branch`)
- **git**: Repositorios Git (`git+https://repo.git`)
- **workspace**: Referencias cruzadas dentro de su monorepo (`workspace:^`)

Para una lista completa, visite https://yarnpkg.com/protocols
