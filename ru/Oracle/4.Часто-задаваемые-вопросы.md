# Часто задаваемые вопросы по Oracle Database

## Вопросы, связанные с установкой

### В1: Что делать при возникновении ошибок прав доступа во время установки?
**О**: Убедитесь, что установка выполняется с использованием пользователя oracle, и что этот пользователь принадлежит группам oinstall и dba. Проверьте конфигурации пользователя и группы в файлах `/etc/passwd` и `/etc/group`.

### В2: Как решить проблемы с недостатком памяти во время установки?
**О**: Oracle Database требует достаточного объема памяти. Решения включают:
- Увеличение физической памяти системы
- Настройка параметров ядра: `kernel.shmmax` и `kernel.shmall`
- Выбор более мелких опций конфигурации во время установки (например, установка класса рабочего стола)

### В3: Как запустить Oracle Database в Docker?
**О**: Oracle предоставляет официальные образы Docker:
```bash
# Oracle Database Free (19c)
docker pull container-registry.oracle.com/database/free:19.3.0.0
docker run -d -p 1521:1521 --name oracle-free container-registry.oracle.com/database/free:19.3.0.0

# Примечание: первоначальный запуск может занять значительное время для инициализации
```

## Проблемы подключения

### В4: Как решить ошибку ORA-12541: TNS:no listener?
**О**: Эта ошибка указывает, что слушатель не запущен. Решения:
```bash
# Запуск слушателя
lsnrctl start

# Проверка статуса слушателя
lsnrctl status

# Убедитесь, что конфигурация слушателя правильная (файл listener.ora)
```

### В5: Ошибка ORA-12170: TNS:Connect timeout occurred?
**О**: Тайм-аут сетевого подключения. Проверьте:
- Доступность сервера базы данных (тест ping)
- Брандмауэр блокирует порт 1521
- Слушатель прослушивает правильный IP-адрес
- Корректность конфигурации tnsnames.ora

### В6: Как сбросить пароли sys/system?
**О**: Используйте инструмент orapwd для сброса файла паролей:
```bash
# Остановка базы данных
sqlplus / as sysdba
SHUTDOWN IMMEDIATE;

# Пересоздание файла паролей
orapwd file=$ORACLE_HOME/dbs/orapw$ORACLE_SID password=new_password force=y

# Запуск базы данных
STARTUP;
```

## Проблемы производительности

### В7: Как оптимизировать медленные запросы?
**О**: Шаги оптимизации производительности:
1. **Анализ плана выполнения**: используйте `EXPLAIN PLAN` для просмотра пути выполнения запроса
2. **Проверка индексов**: убедитесь, что столбцы в предложении WHERE имеют соответствующие индексы
3. **Сбор статистики**: `EXEC DBMS_STATS.GATHER_TABLE_STATS`
4. **Советник по настройке SQL**: используйте Oracle SQL Tuning Advisor
5. **Проверка событий ожидания**: запрос представления `v$session_wait`

### В8: Как просмотреть медленные запросы, выполняющиеся в данный момент?
**О**: Запрос представлений v$session и v$sql:
```sql
SELECT s.sid, s.serial#, s.username, s.status, 
       q.sql_text, q.elapsed_time, q.cpu_time
FROM v$session s, v$sql q
WHERE s.sql_id = q.sql_id
  AND s.status = 'ACTIVE'
  AND q.elapsed_time > 1000000; -- Время выполнения более 1 секунды
```

### В9: Что делать, если использование памяти слишком высоко?
**О**: Настройте параметры памяти:
- **SGA_TARGET**: Общий размер системной глобальной области
- **PGA_AGGREGATE_TARGET**: Общий размер программной глобальной области
- **MEMORY_TARGET**: Автоматическое управление памятью (11g и выше)

```sql
-- Просмотр текущего использования памяти
SHOW PARAMETER memory;
SHOW PARAMETER sga;
SHOW PARAMETER pga;

-- Динамическая настройка (требуются привилегии sysdba)
ALTER SYSTEM SET MEMORY_TARGET = 4G SCOPE=BOTH;
```

## Проблемы резервного копирования и восстановления

### В10: Как обрабатывать сбои резервного копирования RMAN?
**О**: Распространенные проблемы устранения неполадок RMAN:
- **Недостаточно места**: проверьте свободное место в каталоге назначения резервного копирования
- **Проблемы с правами**: убедитесь, что пользователь oracle имеет права на запись в каталог резервного копирования
- **Отсутствующие архивные журналы**: убедитесь, что все архивные журналы доступны
- **Конфигурация каналов**: проверьте, правильно ли настроена конфигурация каналов RMAN

### В11: Как восстановить случайно удаленную таблицу?
**О**: Методы восстановления зависят от стратегии резервного копирования:
1. **Возврат таблицы** (если включен):
   ```sql
   FLASHBACK TABLE table_name TO BEFORE DROP;
   ```
2. **Восстановление на определенный момент времени с помощью RMAN**:
   ```rman
   RUN {
       SET UNTIL TIME "TO_DATE('2026-03-30 08:00:00', 'YYYY-MM-DD HH24:MI:SS')";
       RESTORE DATABASE;
       RECOVER DATABASE;
   }
   ```
3. **Импорт Data Pump**: восстановление из последнего файла экспорта

## Различия между версиями

### В12: В чем основные различия между Oracle Database 19c и 26ai?
**О**: Основные различия включают:
- **Функции ИИ**: 26ai интегрирует функции автоматизированного управления на основе ИИ
- **Оптимизация производительности**: 26ai обеспечивает более интеллектуальное управление ресурсами и оптимизацию запросов
- **Безопасность**: 26ai улучшает возможности мониторинга безопасности и обнаружения угроз
- **Поддержка облачных технологий**: 26ai обеспечивает лучшую поддержку контейнеризации и облачных сред

### В13: На что следует обратить внимание при обновлении с 19c до 26ai?
**О**: Соображения по обновлению:
- **Проверка совместимости**: используйте Database Upgrade Assistant (DBUA) для предварительных проверок
- **Резервное копирование**: полное резервное копирование базы данных должно быть выполнено перед обновлением
- **Тестовая среда**: сначала проверьте процесс обновления в тестовой среде
- **Совместимость приложений**: убедитесь, что приложения совместимы с новой версией
- **Лицензирование**: подтвердите требования к лицензированию для новой версии

## Ежедневное обслуживание

### В14: Как очистить архивные журналы?
**О**: Методы очистки архивных журналов:
```bash
# Использование RMAN для удаления резервных копий архивных журналов
rman target /
DELETE ARCHIVELOG ALL COMPLETED BEFORE 'SYSDATE-7';

# Ручное удаление (не рекомендуется, если только вы не уверены, что они резервированы)
rm $ORACLE_BASE/fast_recovery_area/*/archivelog/*.arc
```

### В15: Что делать, если табличное пространство заполнено?
**О**: Методы расширения табличного пространства:
```sql
-- Добавление файла данных
ALTER TABLESPACE users ADD DATAFILE '/u01/app/oracle/oradata/ORCL/users02.dbf' SIZE 1G;

-- Изменение размера существующего файла данных
ALTER DATABASE DATAFILE '/u01/app/oracle/oradata/ORCL/users01.dbf' RESIZE 2G;

-- Включение автоматического расширения
ALTER DATABASE DATAFILE '/u01/app/oracle/oradata/ORCL/users01.dbf' AUTOEXTEND ON NEXT 100M MAXSIZE UNLIMITED;
```

### В16: Как контролировать состояние работоспособности базы данных?
**О**: Методы мониторинга состояния:
- **Отчеты AWR**: регулярная генерация и анализ отчетов AWR
- **Отчеты ADDM**: автоматический диагностический монитор базы данных
- **OEM**: Oracle Enterprise Manager
- **Пользовательские скрипты**: мониторинг ключевых метрик (количество сессий, блокировки, использование табличного пространства и т.д.)

## Устранение неполадок

### В17: Что делать, если база данных не может запуститься?
**О**: Шаги устранения неполадок запуска:
1. **Проверка журнала предупреждений**: `$ORACLE_BASE/diag/rdbms/<DB_NAME>/trace/alert_<SID>.log`
2. **Проверка файлов управления**: убедитесь, что файлы управления существуют и доступны
3. **Проверка файлов данных**: убедитесь, что все файлы данных существуют
4. **Проверка файла параметров**: убедитесь, что конфигурация spfile или pfile правильная
5. **Попытка режима mount**: `STARTUP MOUNT`, затем пошаговое устранение неполадок

### В18: Как обрабатывать взаимоблокировки (deadlocks)?
**О**: Методы обработки взаимоблокировок:
- **Автоматическая обработка**: Oracle автоматически обнаруживает и завершает одну из транзакций
- **Ручное вмешательство**: запрос `v$lock` и `v$session` для поиска блокирующих сессий и их завершения
  ```sql
  ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE;
  ```
- **Профилактические меры**: обеспечение согласованного порядка доступа на уровне приложения

## Лицензирование и затраты

### В19: Какие ограничения есть у бесплатных версий Oracle Database?
**О**: Ограничения Oracle Database Free (19c/26ai):
- **Ограничение CPU**: максимум 2 CPU
- **Ограничение памяти**: максимум 2 ГБ ОЗУ
- **Ограничение хранилища**: максимум 12 ГБ пользовательских данных
- **Ограничение функций**: не включает расширенные функции корпоративной версии (такие как RAC, Data Guard и т.д.)

### В20: Как снизить затраты на лицензирование Oracle?
**О**: Стратегии оптимизации затрат:
- **Использование бесплатных версий**: для сред разработки и небольших производственных сред
- **Рациональное планирование лицензий CPU**: покупка на основе фактического использования
- **Рассмотрение облачных сервисов**: модели оплаты по использованию, такие как OCI, AWS RDS и т.д.
- **Регулярные аудиты**: обеспечение соответствия лицензированию и предотвращение чрезмерного использования
