# Yarn 使用手冊

## 基本指令對比

### Yarn 4+ (現代版本) vs Yarn Classic (v1)

| 功能 | Yarn 4+ | Yarn Classic |
|------|---------|-------------|
| 初始化專案 | `yarn init -2` | `yarn init` |
| 新增相依性 | `yarn add package` | `yarn add package` |
| 安裝相依性 | `yarn install` | `yarn` 或 `yarn install` |
| 移除相依性 | `yarn remove package` | `yarn remove package` |
| 升級相依性 | `yarn up package` | `yarn upgrade package` |

## Yarn 4+ 進階功能

### 工作區 (Workspaces)

工作區是同一專案中各個獨立套件的名稱，Yarn 會將它們安裝並連結在一起以簡化交叉引用。

#### 宣告工作區
在根目錄的 `package.json` 中新增 `workspaces` 陣列：

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

#### 工作區交叉引用
使用 `workspace:` 通訊協定在工作區之間建立相依關係：

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

#### 聚焦安裝 (Focused Installs)
只安裝特定工作區所需的相依性：

```bash
# 只安裝 @my-org/app 及其相依性
yarn workspaces focus @my-org/app

# 只安裝生產相依性
yarn workspaces focus -A --production
```

#### 平行執行
在多個工作區中平行執行指令：

```bash
# 在所有工作區中發布套件（按拓撲順序）
yarn workspaces foreach --all -pt npm publish

# 只對修改過的工作區執行 lint
yarn workspaces foreach --since run lint

# 對目前工作區及其相依性執行建置
yarn workspaces foreach --from . -R run build
```

### 約束 (Constraints)
約束用於宣告必須應用於專案中特定工作區的規則，類似於程式碼的 ESLint：

- 強制同步所有相依性版本
- 禁止使用某些相依性
- 強制設定 license、engines.node 等欄位

### 全域指令
包含冒號 (`:`) 的指令名稱被視為全域指令，可以從專案中的任何位置執行。

## Yarn Classic 基本用法

### 常用指令
```bash
# 初始化新專案
yarn init

# 新增相依性
yarn add [package]
yarn add [package]@[version]
yarn add [package]@[tag]

# 新增到不同類別的相依性
yarn add [package] --dev      # 開發相依性
yarn add [package] --peer     # 同等相依性  
yarn add [package] --optional # 選擇性相依性

# 升級相依性
yarn upgrade [package]
yarn upgrade [package]@[version]
yarn upgrade [package]@[tag]

# 移除相依性
yarn remove [package]

# 安裝所有相依性
yarn
# 或
yarn install
```

## 版本管理

### Yarn 4+ 版本切換
```bash
# 切換到穩定版本
yarn set version stable

# 切換到 Canary 版本
yarn set version canary

# 從原始碼建置
yarn set version from sources
```

### Yarn Classic 版本管理
Yarn Classic 通常透過 npm 進行版本管理：
```bash
# 升級到最新版本
npm install --global yarn@latest
```

## 最佳實務

### 新專案建議
- 使用 Yarn 4+ 以獲得最新的功能和效能改進
- 充分利用工作區功能管理複雜的專案結構
- 使用約束確保專案一致性

### 現有專案遷移
- 評估現有相依性和工作流程的相容性
- 逐步遷移到現代版本，先在非關鍵專案中測試
- 利用 Yarn 提供的遷移工具和文件

### 效能最佳化
- Yarn 4+ 的平行安裝和離線快取提供更好的效能
- 工作區的聚焦安裝減少不必要的相依性下載
- 利用外掛系統擴充功能而不增加核心複雜性

> **注意**: 本文檔基於官方 yarnpkg.com 和 classic.yarnpkg.com 網站內容整理，包含各版本的詳細使用方法和最佳實務。
