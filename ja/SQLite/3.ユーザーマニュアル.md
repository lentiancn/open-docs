# SQLite ユーザーマニュアル

## 基本的な使用方法

### SQLite コマンドラインシェルの起動

SQLite コマンドラインシェルを起動するには、以下のコマンドを使用します：

```bash
sqlite3 [データベースファイル名]
```

データベースファイルが存在しない場合は、自動的に新規作成されます。

### 基本的な SQL コマンド

#### データベースの作成とテーブルの定義

```sql
-- テーブルの作成
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE,
    age INTEGER,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- インデックスの作成
CREATE INDEX idx_users_email ON users(email);
```

#### データの操作

```sql
-- データの挿入
INSERT INTO users (name, email, age) VALUES ('山田太郎', 'taro@example.com', 25);

-- データの検索
SELECT * FROM users WHERE age > 20;
SELECT name, email FROM users ORDER BY created_at DESC;

-- データの更新
UPDATE users SET age = 26 WHERE name = '山田太郎';

-- データの削除
DELETE FROM users WHERE age < 18;
```

### SQLite 固有のコマンド（ドットコマンド）

SQLite シェルには、SQL 以外の特別なコマンド（ドットコマンド）があります：

- `.help` - ヘルプを表示
- `.tables` - テーブル一覧を表示
- `.schema [テーブル名]` - テーブル定義を表示
- `.dump [テーブル名]` - SQL 形式でデータベースをダンプ
- `.output filename` - 出力をファイルにリダイレクト
- `.mode csv|json|line|column` - 出力フォーマットを設定
- `.quit` - シェルを終了

## データ型

SQLite は動的型付けシステムを採用しており、以下の主要なデータ型をサポートします：

- **NULL** - 空値
- **INTEGER** - 符号付き整数（1、2、3、4、6、8バイト）
- **REAL** - 浮動小数点数（8バイト IEEE 浮動小数点数）
- **TEXT** - テキスト文字列（UTF-8、UTF-16BE、UTF-16LE）
- **BLOB** - バイナリーラージオブジェクト（入力されたままの形式）

### 型親和性

SQLite は「型親和性」という概念を使用し、カラムに格納されるデータの推奨される型を示します。ただし、他のデータ型も格納可能です。

## トランザクションとロック

### トランザクションの基本

```sql
BEGIN TRANSACTION;
INSERT INTO users (name, email) VALUES ('佐藤花子', 'hanako@example.com');
UPDATE users SET age = 30 WHERE name = '山田太郎';
COMMIT;
```

### ロックモード

SQLite は以下のロックモードをサポートします：

- **WAL (Write-Ahead Logging)** - 読み取りと書き込みを同時に可能にするモード
- **DELETE** - 従来のジャーナルモード（デフォルト）

WAL モードを有効にするには：
```sql
PRAGMA journal_mode=WAL;
```

## パフォーマンス最適化

### インデックスの使用

頻繁に検索条件として使用されるカラムにはインデックスを作成しましょう：

```sql
CREATE INDEX idx_users_name ON users(name);
```

### トランザクションのバッチ処理

複数の INSERT/UPDATE 操作は単一のトランザクション内で実行することでパフォーマンスが向上します。

### PRAGMA 設定

パフォーマンスに関連する主な PRAGMA 設定：

```sql
PRAGMA cache_size = 10000;        -- ページキャッシュサイズ
PRAGMA synchronous = NORMAL;      -- 同期レベル
PRAGMA temp_store = MEMORY;       -- 一時テーブルの保存場所
PRAGMA page_size = 4096;          -- ページサイズ
```

## セキュリティ考慮事項

### ファイルパーミッション

SQLite データベースファイルのアクセス権限に注意してください。不正アクセスを防ぐために、適切なファイルパーミッションを設定します。

### SQL インジェクション対策

アプリケーションから SQLite を使用する際は、必ずパラメータ化クエリを使用して SQL インジェクションを防止してください。

### 暗号化

SQLite 自体は暗号化機能を提供していませんが、サードパーティの拡張（SQLCipher など）を使用することでデータベースの暗号化が可能です。

## 制限事項とベストプラクティス

### 制限事項

- 最大データベースサイズ：140TB
- 最大テーブル名長：128文字
- 最大カラム数：2000（コンパイル時設定による）
- 同時書き込み：1つの書き込みと複数の読み取りが可能（WALモード使用時）

### ベストプラクティス

1. **定期的なバックアップ**: `VACUUM` コマンドやファイルコピーによるバックアップを実施
2. **適切なインデックス設計**: 頻繁に使用されるクエリパターンに基づいてインデックスを設計
3. **トランザクションの適切な使用**: アトミック性を保証するために必要な範囲でトランザクションを使用
4. **スキーマのバージョン管理**: アプリケーションのバージョンアップ時にスキーマ変更を適切に管理

## 高度な機能

### 仮想テーブル

SQLite は仮想テーブル機能を提供し、外部データソースをテーブルのように扱うことができます。

### ユーザー定義関数

C/C++、Python、その他の言語でユーザー定義関数を作成し、SQL クエリ内で使用できます。

### FTS (Full-Text Search)

全文検索機能を使用するには、FTS3 または FTS5 仮想テーブルを作成します：

```sql
CREATE VIRTUAL TABLE documents USING fts5(title, content);
INSERT INTO documents VALUES ('タイトル', '本文内容...');
SELECT * FROM documents WHERE documents MATCH '検索キーワード';
```

## トラブルシューティング

### データベースファイルがロックされている

- WAL モードを使用して同時アクセスを改善
- 適切なタイムアウト設定を使用

### パフォーマンスの問題

- EXPLAIN QUERY PLAN を使用してクエリの実行計画を分析
- 不要なインデックスを削除
- 適切な PRAGMA 設定を適用

### データベースの修復

破損したデータベースを修復するには：

```sql
-- データベースの整合性チェック
PRAGMA integrity_check;

-- 自動修復（可能な場合）
PRAGMA wal_checkpoint(RESTART);
```
