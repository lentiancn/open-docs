# Yarn ユーザーマニュアル

## 基本コマンド比較

### Yarn 4+ (モダンバージョン) vs Yarn Classic (v1)

| 機能 | Yarn 4+ | Yarn Classic |
|------|---------|-------------|
| プロジェクト初期化 | `yarn init -2` | `yarn init` |
| 依存関係追加 | `yarn add package` | `yarn add package` |
| 依存関係インストール | `yarn install` | `yarn` または `yarn install` |
| 依存関係削除 | `yarn remove package` | `yarn remove package` |
| 依存関係アップグレード | `yarn up package` | `yarn upgrade package` |

## Yarn 4+ 高度な機能

### ワークスペース (Workspaces)

ワークスペースは同じプロジェクトに属する個別のパッケージのことで、Yarn がそれらをインストールして相互参照を簡素化するためにリンクします。

#### ワークスペースの宣言
ルートの `package.json` に `workspaces` 配列を追加します：

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

#### ワークスペース間の相互参照
ワークスペース間で依存関係を確立するために `workspace:` プロトコルを使用します：

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

#### フォーカスインストール (Focused Installs)
特定のワークスペースに必要な依存関係のみをインストールします：

```bash
# @my-org/app とその依存関係のみをインストール
yarn workspaces focus @my-org/app

# 本番依存関係のみをインストール
yarn workspaces focus -A --production
```

#### 並列実行
複数のワークスペースでスクリプトを並列実行します：

```bash
# すべてのパッケージを並列で公開（トポロジカル順序を尊重）
yarn workspaces foreach --all -pt npm publish

# 変更されたワークスペースでのみ lint を実行
yarn workspaces foreach --since run lint

# 現在のワークスペースとその依存関係でビルドを実行
yarn workspaces foreach --from . -R run build
```

### 制約 (Constraints)
制約はプロジェクト内の特定のワークスペースに適用する必要があるルールを宣言するために使用され、コードの ESLint に似ています：

- プロジェクト全体で依存関係のバージョンを同期することを強制
- 特定の依存関係の使用を禁止
- license や engines.node などのフィールドの適切な設定を強制

### グローバルスクリプト
コロン (`:`) を含むスクリプト名はグローバルスクリプトとして扱われ、プロジェクト内のどこからでも実行できます。

## Yarn Classic 基本的な使用方法

### 一般的なコマンド
```bash
# 新しいプロジェクトを初期化
yarn init

# 依存関係を追加
yarn add [package]
yarn add [package]@[version]
yarn add [package]@[tag]

# 異なる依存関係カテゴリに追加
yarn add [package] --dev      # 開発依存関係
yarn add [package] --peer     # ピア依存関係  
yarn add [package] --optional # オプション依存関係

# 依存関係をアップグレード
yarn upgrade [package]
yarn upgrade [package]@[version]
yarn upgrade [package]@[tag]

# 依存関係を削除
yarn remove [package]

# すべての依存関係をインストール
yarn
# または
yarn install
```

## バージョン管理

### Yarn 4+ バージョン切り替え
```bash
# 安定版に切り替え
yarn set version stable

# Canary バージョンに切り替え
yarn set version canary

# ソースからビルド
yarn set version from sources
```

### Yarn Classic バージョン管理
Yarn Classic は通常 npm を通じてバージョン管理されます：
```bash
# 最新バージョンにアップグレード
npm install --global yarn@latest
```

## ベストプラクティス

### 新規プロジェクトの推奨事項
- 最新の機能とパフォーマンス改善を得るために Yarn 4+ を使用
- 複雑なプロジェクト構造を管理するためにワークスペース機能を十分に活用
- プロジェクトの一貫性を確保するために制約を使用

### 既存プロジェクトの移行
- 既存の依存関係とワークフローの互換性を評価
- 非重要なプロジェクトでまずテストしてから、段階的にモダンバージョンに移行
- Yarn が提供する移行ツールとドキュメントを活用

### パフォーマンス最適化
- Yarn 4+ は並列インストールとオフラインキャッシングにより優れたパフォーマンスを提供
- ワークスペースのフォーカスインストールにより不要な依存関係のダウンロードを削減
- コアの複雑さを増やすことなく機能を拡張するためにプラグインシステムを活用

> **注記**: このドキュメントは yarnpkg.com および classic.yarnpkg.com 公式サイトの内容に基づいており、各バージョンの詳細な使用方法とベストプラクティスを含んでいます。
