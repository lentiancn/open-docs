# Manual del Usuario de Yarn

## Comparación de Comandos Básicos

### Yarn 4+ (Versión Moderna) vs Yarn Classic (v1)

| Función | Yarn 4+ | Yarn Classic |
|---------|---------|-------------|
| Inicializar Proyecto | `yarn init -2` | `yarn init` |
| Añadir Dependencia | `yarn add package` | `yarn add package` |
| Instalar Dependencias | `yarn install` | `yarn` o `yarn install` |
| Eliminar Dependencia | `yarn remove package` | `yarn remove package` |
| Actualizar Dependencia | `yarn up package` | `yarn upgrade package` |

## Funciones Avanzadas de Yarn 4+

### Workspaces

Los workspaces son el nombre de paquetes individuales que forman parte del mismo proyecto y que Yarn instalará y enlazará juntos para simplificar las referencias cruzadas.

#### Declarando Workspaces
Añade un array `workspaces` al `package.json` raíz:

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

#### Referencias Cruzadas de Workspaces
Usa el protocolo `workspace:` para establecer dependencias entre workspaces:

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

#### Instalaciones Enfocadas (Focused Installs)
Instala solo las dependencias requeridas para workspaces específicos:

```bash
# Instalar solo @my-org/app y sus dependencias
yarn workspaces focus @my-org/app

# Instalar solo dependencias de producción
yarn workspaces focus -A --production
```

#### Ejecución Paralela
Ejecuta scripts en paralelo a través de múltiples workspaces:

```bash
# Publicar todos los paquetes en paralelo (respetando el orden topológico)
yarn workspaces foreach --all -pt npm publish

# Ejecutar lint solo en workspaces modificados
yarn workspaces foreach --since run lint

# Ejecutar build en el workspace actual y sus dependencias
yarn workspaces foreach --from . -R run build
```

### Restricciones (Constraints)
Las restricciones se utilizan para declarar reglas que deben aplicarse a workspaces específicos en tu proyecto, similar a ESLint para código:

- Forzar la sincronización de versiones de dependencias en todo el proyecto
- Prevenir el uso de ciertas dependencias
- Forzar configuraciones adecuadas para campos como license, engines.node, etc.

### Scripts Globales
Los nombres de scripts que contienen dos puntos (`:`) se tratan como scripts globales y se pueden ejecutar desde cualquier lugar dentro del proyecto.

## Uso Básico de Yarn Classic

### Comandos Comunes
```bash
# Inicializar nuevo proyecto
yarn init

# Añadir dependencia
yarn add [package]
yarn add [package]@[version]
yarn add [package]@[tag]

# Añadir a diferentes categorías de dependencias
yarn add [package] --dev      # Dependencias de desarrollo
yarn add [package] --peer     # Dependencias peer  
yarn add [package] --optional # Dependencias opcionales

# Actualizar dependencia
yarn upgrade [package]
yarn upgrade [package]@[version]
yarn upgrade [package]@[tag]

# Eliminar dependencia
yarn remove [package]

# Instalar todas las dependencias
yarn
# o
yarn install
```

## Gestión de Versiones

### Cambio de Versión en Yarn 4+
```bash
# Cambiar a versión estable
yarn set version stable

# Cambiar a versión Canary
yarn set version canary

# Construir desde fuentes
yarn set version from sources
```

### Gestión de Versiones en Yarn Classic
Yarn Classic normalmente se gestiona a través de npm:
```bash
# Actualizar a la última versión
npm install --global yarn@latest
```

## Mejores Prácticas

### Recomendaciones para Nuevos Proyectos
- Usa Yarn 4+ para obtener las últimas funciones y mejoras de rendimiento
- Aprovecha completamente la funcionalidad de workspaces para gestionar estructuras de proyectos complejas
- Usa restricciones para garantizar la consistencia del proyecto

### Migración de Proyectos Existentes
- Evalúa la compatibilidad de las dependencias y flujos de trabajo existentes
- Migra gradualmente a la versión moderna, probando primero en proyectos no críticos
- Aprovecha las herramientas y documentación de migración de Yarn

### Optimización de Rendimiento
- Yarn 4+ proporciona mejor rendimiento a través de instalaciones paralelas y caché offline
- Las instalaciones enfocadas en workspaces reducen las descargas innecesarias de dependencias
- Aprovecha el sistema de plugins para extender funcionalidades sin aumentar la complejidad del núcleo

> **Nota**: Este documento se basa en el contenido oficial de los sitios web yarnpkg.com y classic.yarnpkg.com, incluyendo métodos de uso detallados y mejores prácticas para cada versión.
