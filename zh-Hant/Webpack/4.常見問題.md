# Webpack 常見問題

## 安裝相關問題

### Q：我應該全域安裝 Webpack 還是本地安裝？
**A**：始終將 Webpack 作為開發依賴本地安裝。全域安裝可能導致專案之間的版本衝突，並使管理不同專案的 Webpack 版本更加困難。

### Q：webpack 和 webpack-cli 有什麼區別？
**A**：
- **webpack**：核心捆綁引擎
- **webpack-cli**：提供 CLI 命令的命令列介面

基本使用需要兩者。將它們一起安裝：`npm install --save-dev webpack webpack-cli`

### Q：如何選擇 Webpack v4 和 v5？
**A**：
- **新專案**：使用 Webpack v5 以獲得更好的效能、持久化快取和現代特性
- **現有專案**：如果已在使用 v4，可以繼續使用或遷移至 v5
- **企業環境**：v4 提供穩定的長期支援，而 v5 提供尖端特性

## 配置相關問題

### Q：我需要配置檔案嗎？
**A**：自 Webpack 4 起，基本使用不需要配置檔案。Webpack 將使用預設設定並尋找 `./src/index.js` 作為入口點。然而，大多數實際專案都需要自定义配置。

### Q：Webpack 配置中的 CommonJS 和 ES 模組有什麼區別？
**A**：
- **CommonJS**（Webpack v4 風格）：使用 `module.exports` 和 `require()`
- **ES 模組**（Webpack v5 風格）：使用 `export default` 和 `import`

Webpack v5 支援兩者，但新專案推薦使用 ES 模組。

### Q：如何處理多個入口點？
**A**：在 entry 配置中指定一個物件：

```javascript
export default {
  entry: {
    app: './src/app.js',
    admin: './src/admin.js'
  }
};
```

這將為每個入口點建立單獨的捆綁包。

## 效能相關問題

### Q：為什麼我的建構這麼慢？
**A**：常見原因和解決方案：
- **大型 node_modules**：使用 `SplitChunksPlugin` 分割 vendor 程式碼
- **無快取**：在 Webpack v5 中啟用持久化快取
- **多個 loaders**：最佳化 loader 配置並使用 include/exclude 規則
- **Source maps**：在開發中使用更快的 source map 類型（`eval` 而非 `source-map`）

### Q：如何為生產建構啟用快取？
**A**：在輸出檔名中使用內容雜湊：

```javascript
output: {
  filename: '[name].[contenthash].js',
  chunkFilename: '[name].[contenthash].js'
}
```

這確保檔案僅在其內容變更時才會變更，從而允許瀏覽器有效快取它們。

### Q：Webpack v5 中的持久化快取是什麼？
**A**：持久化快取在多次執行之間將建構資訊儲存在磁碟上，顯著加速後續建構。使用以下方式啟用：

```javascript
cache: {
  type: 'filesystem'
}
```

## 開發相關問題

### Q：如何設置熱模組替換（HMR）？
**A**：使用啟用 HMR 的 webpack-dev-server：

```javascript
// webpack.config.js
export default {
  devServer: {
    hot: true
  }
};
```

並在您的應用程式中新增 HMR 程式碼：

```javascript
if (module.hot) {
  module.hot.accept('./module', () => {
    // 處理更新
  });
}
```

### Q：如何除錯我的捆綁程式碼？
**A**：在配置中啟用 source maps：

```javascript
export default {
  devtool: 'source-map' // 用於生產
  // 或
  devtool: 'eval-source-map' // 用於開發（更快）
};
```

這允許您在瀏覽器的開發人員工具中除錯您的原始碼。

### Q：如何處理 CSS 和圖片？
**A**：使用合適的 loaders 或 Webpack v5 的內建資產模組：

**Webpack v5（推薦）：**
```javascript
module: {
  rules: [
    {
      test: /\.css$/,
      use: ['style-loader', 'css-loader']
    },
    {
      test: /\.(png|svg|jpg|jpeg|gif)$/i,
      type: 'asset/resource'
    }
  ]
}
```

**Webpack v4：**
```javascript
module: {
  rules: [
    {
      test: /\.css$/,
      use: ['style-loader', 'css-loader']
    },
    {
      test: /\.(png|svg|jpg|jpeg|gif)$/i,
      use: ['file-loader']
    }
  ]
}
```

## 遷移問題

### Q：如何從 Webpack v4 遷移到 v5？
**A**：按照以下步驟操作：
1. 更新依賴：`npm install webpack@latest webpack-cli@latest`
2. 查閱官方遷移指南中的破壞性變更
3. 用 asset 模組替換 file-loader/url-loader
4. 更新外掛程式配置以相容 Webpack v5
5. 進行全面測試以確保一切正常運作

### Q：Webpack v5 中的 file-loader 和 url-loader 发生了什麼變化？
**A**：Webpack v5 引入了內建資產模組，替換了 file-loader 和 url-loader：

- **asset/resource**：取代 file-loader（發出單獨的檔案）
- **asset/inline**：取代 url-loader（作為 data URLs 內嵌）
- **asset**：根據檔案大小自動選擇 resource 或 inline

### Q：我現有的外掛程式是否與 Webpack v5 相容？
**A**：大多數受歡迎的外掛程式都已更新以相容 Webpack v5。請檢查外掛程式的文件或 npm 頁面以獲取 Webpack v5 支援。如果外掛程式不相容，請尋找替代方案或檢查是否有可用的測試版本。

## 進階使用問題

### Q：模組聯合（Module Federation）是什麼？
**A**：模組聯合是 Webpack v5 的特性，可實現跨單獨應用程式在執行時共享程式碼。對於不同團隊擁有應用程式不同部分的微前端架構尤其有用。

### Q：如何最佳化捆綁大小？
**A**：多種策略：
- **程式碼分割**：將程式碼分割為按需載入的小塊
- **Tree Shaking**：移除未使用的程式碼（確保使用 ES6 模組）
- **壓縮**：在生產模式中啟用壓縮
- **壓縮**：使用壓縮外掛程式如 CompressionWebpackPlugin
- **捆綁分析**：使用 webpack-bundle-analyzer 識別大型依賴

### Q：如何處理環境變數？
**A**：使用 DefinePlugin 注入環境變數：

```javascript
import webpack from 'webpack';

export default {
  plugins: [
    new webpack.DefinePlugin({
      'process.env.NODE_ENV': JSON.stringify('production'),
      'process.env.API_URL': JSON.stringify('https://api.example.com')
    })
  ]
};
```

這些變數將在建構時被其實際值替換。
