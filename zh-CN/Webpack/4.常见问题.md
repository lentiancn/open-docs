# Webpack 常见问题

## 安装相关问题

### Q: 我应该全局安装 Webpack 还是本地安装？
**A**: 始终将 Webpack 作为开发依赖进行本地安装。全局安装可能导致项目间的版本冲突，并使管理不同 Webpack 版本变得更加困难。

### Q: webpack 和 webpack-cli 有什么区别？
**A**: 
- **webpack**: 核心打包引擎
- **webpack-cli**: 提供 CLI 命令的命令行界面

基本使用需要两者。一起安装：`npm install --save-dev webpack webpack-cli`

### Q: 如何在 Webpack v4 和 v5 之间选择？
**A**: 
- **新项目**: 使用 Webpack v5 以获得更好的性能、持久化缓存和现代特性
- **现有项目**: 如果已在使用 v4，可以继续使用或升级到 v5
- **企业环境**: v4 提供稳定的长期支持，v5 提供前沿功能

## 配置相关问题

### Q: 我需要配置文件吗？
**A**: 从 Webpack 4 开始，基本使用不需要配置文件。Webpack 将使用默认设置并查找 `./src/index.js` 作为入口点。然而，大多数实际项目需要自定义配置。

### Q: Webpack 配置中 CommonJS 和 ES Module 的区别是什么？
**A**: 
- **CommonJS**（Webpack v4 风格）: 使用 `module.exports` 和 `require()`
- **ES Module**（Webpack v5 风格）: 使用 `export default` 和 `import`

Webpack v5 支持两者，但新项目推荐使用 ES Module。

### Q: 如何处理多个入口点？
**A**: 在 entry 配置中指定对象：

```javascript
export default {
  entry: {
    app: './src/app.js',
    admin: './src/admin.js'
  }
};
```

这将为每个入口点创建单独的打包文件。

## 性能相关问题

### Q: 为什么我的构建速度这么慢？
**A**: 常见原因及解决方案：
- **庞大的 node_modules**: 使用 `SplitChunksPlugin` 分离供应商代码
- **没有缓存**: 在 Webpack v5 中启用持久化缓存
- **加载器过多**: 优化加载器配置并使用 include/exclude 规则
- **Source maps**: 在开发中使用更快的 source map 类型（`eval` 代替 `source-map`）

### Q: 如何为生产构建启用缓存？
**A**: 在输出文件名中使用内容哈希：

```javascript
output: {
  filename: '[name].[contenthash].js',
  chunkFilename: '[name].[contenthash].js'
}
```

这确保文件仅在其内容更改时才会更改，允许浏览器有效缓存它们。

### Q: Webpack v5 中的持久化缓存是什么？
**A**: 持久化缓存在运行之间将构建信息存储在磁盘上，显著加快后续构建速度。启用方式：

```javascript
cache: {
  type: 'filesystem'
}
```

## 开发相关问题

### Q: 如何设置热模块替换（HMR）？
**A**: 使用启用了 HMR 的 webpack-dev-server：

```javascript
// webpack.config.js
export default {
  devServer: {
    hot: true
  }
};
```

并在您的应用程序中添加 HMR 代码：

```javascript
if (module.hot) {
  module.hot.accept('./module', () => {
    // 处理更新
  });
}
```

### Q: 如何调试我的打包代码？
**A**: 在配置中启用 source maps：

```javascript
export default {
  devtool: 'source-map' // 用于生产环境
  // 或
  devtool: 'eval-source-map' // 用于开发环境（更快）
};
```

这允许您在浏览器的开发者工具中调试原始源代码。

### Q: 如何处理 CSS 和图片？
**A**: 使用适当的加载器或 Webpack v5 的内置资源模块：

**Webpack v5（推荐）：**
```javascript
module: {
  rules: [
    {
      test: /\.css$/,
      use: ['style-loader', 'css-loader']
    },
    {
      test: /\.(png|svg|jpg|jpeg|gif)$/i,
      type: 'asset/resource'
    }
  ]
}
```

**Webpack v4：**
```javascript
module: {
  rules: [
    {
      test: /\.css$/,
      use: ['style-loader', 'css-loader']
    },
    {
      test: /\.(png|svg|jpg|jpeg|gif)$/i,
      use: ['file-loader']
    }
  ]
}
```

## 迁移相关问题

### Q: 如何从 Webpack v4 迁移到 v5？
**A**: 按照以下步骤操作：
1. 更新依赖：`npm install webpack@latest webpack-cli@latest`
2. 查阅官方迁移指南了解破坏性变更
3. 用资源模块替换 file-loader/url-loader
4. 更新插件配置以兼容 Webpack v5
5. 彻底测试以确保一切正常工作

### Q: Webpack v5 中的 file-loader 和 url-loader 怎么了？
**A**: Webpack v5 引入了内置资源模块来替换 file-loader 和 url-loader：

- **asset/resource**: 替换 file-loader（输出单独的文件）
- **asset/inline**: 替换 url-loader（以内联数据 URL 形式）
- **asset**: 根据文件大小自动选择 resource 或 inline

### Q: 我现有的插件与 Webpack v5 兼容吗？
**A**: 大多数流行插件都已更新以兼容 Webpack v5。请检查插件的文档或 npm 页面以了解 Webpack v5 支持。如果插件不兼容，请寻找替代方案或检查是否有可用的测试版本。

## 高级使用问题

### Q: 什么是模块联合（Module Federation）？
**A**: 模块联合是 Webpack v5 的一个特性，允许在运行时在 separate 应用程序之间共享代码。它特别适用于微前端架构，其中不同的团队拥有应用程序的不同部分。

### Q: 如何优化打包文件大小？
**A**: 多种策略：
- **代码分割**: 将代码分割成按需加载的小块
- **Tree Shaking**: 移除未使用的代码（确保您使用的是 ES6 模块）
- **压缩**: 在生产模式下启用压缩
- **压缩**: 使用压缩插件如 CompressionWebpackPlugin
- **分析打包文件**: 使用 webpack-bundle-analyzer 识别大型依赖

### Q: 如何处理环境变量？
**A**: 使用 DefinePlugin 注入环境变量：

```javascript
import webpack from 'webpack';

export default {
  plugins: [
    new webpack.DefinePlugin({
      'process.env.NODE_ENV': JSON.stringify('production'),
      'process.env.API_URL': JSON.stringify('https://api.example.com')
    })
  ]
};
```

这些变量将在构建时被其实际值替换。
