# Manual de Usuario de Yarn

## Comandos Básicos

### Comandos Generales

- `yarn add` - Añadir dependencias al proyecto
- `yarn install` - Instalar las dependencias del proyecto
- `yarn remove` - Eliminar dependencias del proyecto
- `yarn run` - Ejecutar un script definido en package.json
- `yarn init` - Crear un nuevo paquete
- `yarn info` - Ver información relacionada con los paquetes
- `yarn why` - Mostrar el motivo por el que se necesita un paquete

### Comandos Avanzados

- `yarn dlx` - Ejecutar un paquete en un entorno temporal
- `yarn dedupe` - Eliminar dependencias con rangos superpuestos
- `yarn up` - Actualizar dependencias en todo el proyecto
- `yarn pack` - Generar un tarball desde el workspace activo
- `yarn rebuild` - Reconstruir los paquetes nativos del proyecto

### Comandos Relacionados con NPM

- `yarn npm audit` - Realizar una auditoría de vulnerabilidades contra los paquetes instalados
- `yarn npm publish` - Publicar el workspace activo en el registro npm
- `yarn npm login` - Almacenar nueva información de inicio de sesión para acceder al registro npm
- `yarn npm logout` - Cerrar sesión del registro npm
- `yarn npm whoami` - Mostrar el nombre del usuario autenticado

### Gestión de Plugins

- `yarn plugin list` - Listar los plugins oficiales disponibles
- `yarn plugin import` - Descargar un plugin
- `yarn plugin remove` - Eliminar un plugin
- `yarn plugin runtime` - Listar los plugins activos

## Workspaces

Yarn fue el primer gestor de paquetes construido específicamente alrededor de workspaces, permitiéndole dividir su proyecto en sub-componentes.

### Configuración de Workspaces

Configure los workspaces en su `package.json` raíz:

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

### Comandos de Workspaces

- `yarn workspaces list` - Listar todos los workspaces
- `yarn workspace <name> <command>` - Ejecutar un comando en un workspace específico

### Referencias Cruzadas

Los paquetes de monorepos a menudo necesitan depender unos de otros. Yarn lo hace muy fácil gracias al protocolo especial `workspace:`:

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

El protocolo `workspace:` acepta tanto un rango semver regular como los tokens especiales `^` / `~` / `*`.

### Instalaciones Limitadas

Una preocupación común al descubrir workspaces es que necesita instalar todas sus dependencias cada vez que desea trabajar en una sola de ellas. Yarn proporciona una solución mediante `yarn workspaces focus`.

Este comando toma una lista de workspaces, extiende la lista para incluir dependencias transitivas, y excluye todo lo demás de la instalación:

```bash
yarn workspaces focus @my-org/app
```

### Ejecución Paralela

Los scripts de múltiples workspaces pueden ejecutarse en paralelo si comparten el mismo nombre, usando `yarn workspaces foreach`:

```bash
yarn workspaces foreach --all -pt npm publish
```

## Plug'n'Play (PnP)

Yarn Plug'n'Play (PnP) es la estrategia de instalación predeterminada en las versiones modernas de Yarn. Reemplaza la carpeta tradicional node_modules con un único archivo de cargador de Node.js (.pnp.cjs).

### Ventajas de PnP

- **Huella de instalación mínima**: Sin copia de archivos, solo genera un archivo de cargador
- **Instalaciones compartidas entre discos**: Reutiliza los artefactos de paquetes en todos los proyectos
- **Hoisting perfecto y correcto**: Elimina las dependencias fantasma
- **Protección contra dependencias fantasma**: Previene el acceso a dependencias no declaradas
- **Semantic erroring**: Proporciona mensajes de error claros y accionables

### Consideraciones de Migration

- Los nuevos proyectos funcionan casi directamente con PnP
- Los proyectos existentes pueden requerir la corrección de dependencias fantasma usando packageExtensions
- Se puede revertir a node_modules en cualquier momento configurando `nodeLinker: node-modules` en .yarnrc.yml

## Archivos de Configuración

### .yarnrc.yml

Yarn v2+ usa el archivo `.yarnrc.yml` para configuración:

```yaml
nodeLinker: pnp
yarnPath: .yarn/releases/yarn-4.0.0.cjs
packageExtensions:
  "@babel/core@*":
    dependencies:
      "@babel/types": "*"
```

### .yarnrc (Yarn v1)

Yarn v1 usa el archivo `.yarnrc`:

```
--registry https://registry.npmjs.org
--strict-semver true
```

## Diferencias de Versión

### Yarn v4+ vs Yarn v1

| Característica | Yarn v4+ | Yarn v1 |
|----------------|----------|---------|
| Arquitectura | Basada en plugins (Berry) | Tradicional |
| Velocidad de Instalación | Más rápida (instalaciones paralelas) | Velocidad estándar |
| Espacio en Disco | Más eficiente (PnP) | node_modules estándar |
| Workspaces | Soporte nativo | Requiere configuración adicional |
| Sistema de Plugins | Soporte integrado | No soportado |
| Configuración | .yarnrc.yml | .yarnrc |

### Consideraciones de Migración

- Yarn v4+ usa PnP por defecto, lo cual puede ser incompatible con algunas herramientas
- Las configuraciones de CI/CD necesitan actualizarse para acomodar el nuevo flujo de instalación
- El sistema de plugins proporciona más opciones de personalización
- La funcionalidad de workspace es más potente y flexible
