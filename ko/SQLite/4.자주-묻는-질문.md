# SQLite 자주 묻는 질문 (FAQ)

## 1. AUTOINCREMENT 필드를 어떻게 생성하나요?

**간단한 답변**: `INTEGER PRIMARY KEY`로 선언된 열은 자동으로 증가합니다.

**자세한 설명**: 테이블의 열을 `INTEGER PRIMARY KEY`로 선언하면, 해당 열에 NULL을 삽입할 때마다 자동으로 이전 최대값보다 1 큰 정수로 변환됩니다. 예:

```sql
CREATE TABLE t1(
  a INTEGER PRIMARY KEY,
  b INTEGER
);

INSERT INTO t1 VALUES(NULL, 123);
-- 위 문장은 다음 문장과 논리적으로 동일합니다:
-- INSERT INTO t1 VALUES((SELECT max(a) FROM t1)+1, 123);
```

가장 최근에 삽입된 행의 키 값을 얻으려면 `sqlite3_last_insert_rowid()` 함수를 사용하세요.

**AUTOINCREMENT 키워드**: 일반적인 자동 증가와 달리, `AUTOINCREMENT` 키워드를 사용하면 테이블의 전체 수명 동안 고유한 키 값을 보장합니다. 이 경우 키는 테이블에 ever 존재했던 가장 큰 키 값보다 1 크게 선택됩니다.

```sql
CREATE TABLE t2(
  a INTEGER PRIMARY KEY AUTOINCREMENT,
  b INTEGER
);
```

## 2. SQLite는 어떤 데이터 타입을 지원하나요?

SQLite는 **동적 타이핑**(dynamic typing)을 사용합니다. 데이터는 다음 다섯 가지 스토리지 클래스 중 하나로 저장될 수 있습니다:

- **INTEGER**: 부호 있는 정수
- **REAL**: 부동 소수점 숫자
- **TEXT**: 텍스트 문자열
- **BLOB**: 바이너리 대용량 객체
- **NULL**: NULL 값

## 3. SQLite가 정수형 열에 문자열을 삽입하도록 허용하는 이유는 무엇인가요?

이는 버그가 아니라 **기능**입니다. SQLite는 동적 타이핑을 사용하며 데이터 타입 제약을 강제하지 않습니다. `CREATE TABLE` 명령에서 열에 할당한 데이터 타입은 해당 형식의 값을 선호한다는 **힌트**일 뿐입니다.

SQLite는 **타입 선호도**(type affinity)라는 기능을 사용합니다. 예를 들어, INTEGER 타입의 열에 문자열을 삽입하려고 하면 SQLite는 문자열을 정수로 변환하려고 시도합니다. 변환이 가능하면 정수를 삽입하고, 그렇지 않으면 원래 문자열을 삽입합니다.

단, `INTEGER PRIMARY KEY` 열은 예외로, 64비트 부호 있는 정수만 허용됩니다.

## 4. 왜 '0'과 '0.0'을 동일 테이블의 기본 키로 사용할 수 없나요?

숫자형 기본 키를 사용할 때 발생하는 문제입니다. SQLite는 '0'과 '0.0'을 수치적으로 동일하게 비교하기 때문에 고유하지 않은 값으로 간주합니다.

해결 방법은 기본 키의 데이터 타입을 **TEXT**로 변경하는 것입니다:
```sql
CREATE TABLE mytable(
  id TEXT PRIMARY KEY,
  ...
);
```

## 5. 여러 애플리케이션이 동일한 데이터베이스 파일에 동시에 접근할 수 있나요?

**네**, 여러 프로세스가 동일한 데이터베이스 파일을 동시에 열 수 있습니다.

- **읽기 작업**: 여러 프로세스가 동시에 SELECT를 실행할 수 있습니다.
- **쓰기 작업**: 한 번에 하나의 프로세스만 데이터베이스를 수정할 수 있습니다.

SQLite는 읽기/쓰기 잠금(reader/writer locks)을 사용하여 동시 접근을 제어합니다. 그러나 NFS 파일 시스템에서는 잠금 메커니즘이 제대로 작동하지 않을 수 있으므로 피해야 합니다.

쓰기 작업을 기다리는 동안 다른 프로세스는 `SQLITE_BUSY` 오류를 받습니다. 이를 처리하려면 C 코드에서 `sqlite3_busy_handler()` 또는 `sqlite3_busy_timeout()` API 함수를 사용할 수 있습니다.

## 6. SQLite는 스레드 안전(threadsafe)한가요?

**네**, SQLite는 스레드 안전합니다. 하지만 다음 조건이 필요합니다:

- SQLite 라이브러리가 `SQLITE_THREADSAFE` 전처리기 매크로를 1로 설정하여 컴파일되어야 합니다.
- Windows 및 Linux 배포판의 미리 컴파일된 바이너리는 이 방식으로 컴파일되어 있습니다.

스레드 안전을 확인하려면 `sqlite3_threadsafe()` 인터페이스를 호출하세요.

성능을 최적화하려면 스레드 안전이 필요하지 않은 경우 뮤텍스를 비활성화할 수 있습니다.

## 7. SQLite 데이터베이스에 포함된 모든 테이블/인덱스 목록을 어떻게 확인하나요?

### CLI에서:
- `.tables` - 모든 테이블 목록 표시
- `.schema` - 전체 데이터베이스 스키마 표시

### SQL 쿼리로:
```sql
-- 모든 테이블 목록
SELECT name FROM sqlite_schema
WHERE type='table'
ORDER BY name;

-- 모든 인덱스 목록  
SELECT name FROM sqlite_schema
WHERE type='index'
ORDER BY name;

-- 임시 테이블 포함 모든 테이블
SELECT name FROM
(SELECT * FROM sqlite_schema UNION ALL
 SELECT * FROM sqlite_temp_schema)
WHERE type='table'
ORDER BY name;
```

## 8. SQLite 데이터베이스의 크기 제한이 있나요?

SQLite에는 다양한 제한 사항이 있습니다. 자세한 내용은 [limits.html](https://www.sqlite.org/limits.html) 문서를 참조하세요.

주요 제한 사항:
- **최대 데이터베이스 크기**: 140TB (2^47 바이트)
- **최대 행 크기**: 약 2GB
- **최대 열 수**: 기본값 2000개 (컴파일 시 조정 가능)
- **최대 테이블 수**: 제한 없음 (실제로는 디스크 공간에 따라 제한됨)

## 9. SQLite에서 VARCHAR의 최대 크기는 얼마인가요?

SQLite는 VARCHAR 길이를 강제하지 않습니다. `VARCHAR(10)`으로 선언해도 5억 자의 문자열을 저장할 수 있으며 잘리지 않습니다.

SQLite는 `"VARCHAR(N)"` 열 타입을 `"TEXT"`와 동일하게 취급합니다.

## 10. SQLite는 BLOB 타입을 지원하나요?

**네**, SQLite는 BLOB 데이터를 지원합니다. BLOB 데이터는 선언된 타입과 관계없이 모든 열에 저장할 수 있으며, 심지어 PRIMARY KEY로도 사용할 수 있습니다.

## 11. 기존 테이블에 열을 추가, 삭제 또는 이름 변경하려면 어떻게 해야 하나요?

SQLite는 제한된 `ALTER TABLE` 지원을 제공합니다:

- **열 추가**: `ALTER TABLE table_name ADD COLUMN column_definition`
- **테이블 이름 변경**: `ALTER TABLE old_name RENAME TO new_name`
- **열 이름 변경**: `ALTER TABLE table_name RENAME COLUMN old_name TO new_name`

더 복잡한 구조 변경이 필요한 경우 테이블을 재생성해야 합니다:

1. 기존 데이터를 임시 테이블에 저장
2. 기존 테이블 삭제
3. 새 구조로 테이블 생성
4. 임시 테이블에서 데이터 복사

## 12. 많은 데이터를 삭제했는데 데이터베이스 파일 크기가 줄어들지 않는 이유는?

삭제된 데이터의 디스크 공간은 내부 "free-list"에 추가되어 다음 삽입 작업에서 재사용됩니다. 운영 체제에는 반환되지 않습니다.

데이터베이스 파일 크기를 줄이려면 `VACUUM` 명령을 실행하세요:
```sql
VACUUM;
```

`VACUUM`은 데이터베이스를 처음부터 재구성하여 최소 크기의 파일을 생성합니다. 하지만 실행 시간이 걸리고 임시로 두 배의 디스크 공간이 필요합니다.

대안으로는 `auto_vacuum` 모드를 활성화할 수 있습니다:
```sql
PRAGMA auto_vacuum = FULL; -- 또는 INCREMENTAL
```

## 13. 상업 제품에서 SQLite를 사용해도 로열티를 지불해야 하나요?

**아니요**. SQLite는 **공개 도메인**(public domain)에 있으며 어떤 목적(상업적 또는 개인적)으로든 자유롭게 사용할 수 있습니다. 저작권 주장이 없으며 아무런 제한 없이 사용할 수 있습니다.

## 14. 내장된 작은따옴표(')가 포함된 문자열 리터럴을 어떻게 사용하나요?

SQL 표준에 따라 작은따옴표는 두 개를 연속으로 사용하여 이스케이프합니다:
```sql
INSERT INTO xyz VALUES('5 O''clock');
```

## 15. SQLITE_SCHEMA 오류는 무엇이며 왜 발생하나요?

`SQLITE_SCHEMA` 오류는 준비된(prepared) SQL 문이 더 이상 유효하지 않아 실행할 수 없을 때 반환됩니다.

이 오류는 `sqlite3_prepare()` 및 `sqlite3_step()` 인터페이스를 사용할 때만 발생합니다. 해결 방법:

- `sqlite3_prepare_v2()`를 사용하세요. 이 인터페이스는 스키마 변경 시 자동으로 문을 재컴파일합니다.
- 오류 발생 시 SQL 문을 다시 준비(prepapre)하세요.

## 16. INSERT가 매우 느린 이유는?

SQLite는 초당 수십 개의 **트랜잭션**만 처리할 수 있습니다. 디스크 드라이브의 회전 속도에 의해 제한됩니다.

각 INSERT 문은 기본적으로 자체 트랜잭션입니다. 성능을 개선하려면 여러 INSERT 문을 하나의 트랜잭션으로 그룹화하세요:

```sql
BEGIN;
INSERT INTO ...;
INSERT INTO ...;
-- ... 더 많은 INSERT 문
COMMIT;
```

또는 동기화를 비활성화할 수 있지만, 이 경우 전원 장애 시 데이터베이스가 손상될 위험이 있습니다:
```sql
PRAGMA synchronous = OFF;
```

## 17. 실수로 중요한 데이터를 삭제했습니다. 어떻게 복구하나요?

백업이 있다면 백업에서 복구하세요.

백업이 없는 경우 복구는 매우 어렵습니다. 다음과 같은 경우에만 부분적으로 복구가 가능할 수 있습니다:

- `SQLITE_SECURE_DELETE` 옵션이 사용되지 않은 경우
- 데이터 삭제 후 `VACUUM` 명령을 실행하지 않은 경우

이 경우 원시 데이터베이스 파일의 바이너리 덤프에서 부분적인 문자열 데이터를 찾을 수 있습니다.

## 18. SQLITE_CORRUPT 오류는 무엇인가요?

`SQLITE_CORRUPT` 오류는 SQLite가 데이터베이스 파일의 구조, 형식 또는 기타 제어 요소에 오류를 감지했을 때 반환됩니다.

SQLite 자체는 데이터베이스 파일을 손상시키지 않습니다. 손상은 일반적으로 외부 요인(하드웨어 결함, OS 버그, 애플리케이션 버그 등)으로 인해 발생합니다.

무결성 검사를 위해 다음 명령어를 사용할 수 있습니다:
```sql
PRAGMA integrity_check;  -- 철저하지만 시간이 오래 걸림
PRAGMA quick_check;      -- 빠르지만 덜 철저함
```

## 19. SQLite는 외래 키(Foreign Key)를 지원하나요?

버전 3.6.19(2009-10-14)부터 SQLite는 외래 키 제약 조건을 지원합니다.

**주의**: 외래 키 제약 조건 시행은 기본적으로 **비활성화**되어 있습니다(이전 버전과의 호환성을 위해).

외래 키를 활성화하려면:
```sql
PRAGMA foreign_keys = ON;
```

또는 컴파일 시 `-DSQLITE_DEFAULT_FOREIGN_KEYS=1` 옵션을 사용하세요.

## 20. 내 쿼리에서 예상한 열 이름이 반환되지 않는 이유는?

`AS` 절을 사용한 경우 SQLite는 `AS` 키워드 오른쪽의 식별자를 열 이름으로 사용합니다.

`AS` 절을 사용하지 않은 경우 SQLite는 열 이름을 자유롭게 지정할 수 있습니다. 이는 버그가 아닙니다.

## 21. 내 데이터베이스가 어디로 갔나요? (또는: 데이터베이스가 비어있어졌습니다!)

SQLite는 존재하지 않는 데이터베이스 파일을 열려고 하면 자동으로 새로 생성합니다. 새로 생성된 데이터베이스는 초기에 비어 있습니다.

이 문제는 일반적으로 다음 경우에 발생합니다:
- 파일 이름 오타
- 상대 경로 사용 시 현재 작업 디렉토리가 다른 경우
- 다른 컨텍스트에서 다른 데이터베이스 파일을 여는 경우
