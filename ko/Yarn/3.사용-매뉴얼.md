# Yarn 사용 매뉴얼

## 기본 명령어 비교

### Yarn 4+ (모던 버전) vs Yarn Classic (v1)

| 기능 | Yarn 4+ | Yarn Classic |
|------|---------|-------------|
| 프로젝트 초기화 | `yarn init -2` | `yarn init` |
| 의존성 추가 | `yarn add package` | `yarn add package` |
| 의존성 설치 | `yarn install` | `yarn` 또는 `yarn install` |
| 의존성 제거 | `yarn remove package` | `yarn remove package` |
| 의존성 업그레이드 | `yarn up package` | `yarn upgrade package` |

## Yarn 4+ 고급 기능

### 워크스페이스 (Workspaces)

워크스페이스는 동일한 프로젝트의 일부인 개별 패키지의 이름이며, Yarn은 이를 설치하고 크로스 참조를 단순화하기 위해 함께 연결합니다.

#### 워크스페이스 선언
루트 `package.json`에 `workspaces` 배열을 추가하세요:

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

#### 워크스페이스 간 크로스 참조
워크스페이스 간 의존성을 설정하려면 `workspace:` 프로토콜을 사용하세요:

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

#### 포커스 설치 (Focused Installs)
특정 워크스페이스에 필요한 의존성만 설치하세요:

```bash
# @my-org/app 및 해당 의존성만 설치
yarn workspaces focus @my-org/app

# 프로덕션 의존성만 설치
yarn workspaces focus -A --production
```

#### 병렬 실행
여러 워크스페이스에서 스크립트를 병렬로 실행하세요:

```bash
# 모든 패키지를 병렬로 게시 (위상 순서 존중)
yarn workspaces foreach --all -pt npm publish

# 수정된 워크스페이스에서만 lint 실행
yarn workspaces foreach --since run lint

# 현재 워크스페이스 및 해당 의존성에서 빌드 실행
yarn workspaces foreach --from . -R run build
```

### 제약 조건 (Constraints)
제약 조건은 프로젝트 내 특정 워크스페이스에 적용해야 하는 규칙을 선언하는 데 사용되며, 코드의 ESLint와 유사합니다:

- 프로젝트 전체에서 의존성 버전 동기화 강제
- 특정 의존성 사용 방지
- license, engines.node 등의 필드에 적절한 설정 강제

### 글로벌 스크립트
콜론(`:`)을 포함하는 스크립트 이름은 글로벌 스크립트로 처리되며, 프로젝트 내 어디서나 실행할 수 있습니다.

## Yarn Classic 기본 사용법

### 일반적인 명령어
```bash
# 새 프로젝트 초기화
yarn init

# 의존성 추가
yarn add [package]
yarn add [package]@[version]
yarn add [package]@[tag]

# 다른 의존성 카테고리에 추가
yarn add [package] --dev      # 개발 의존성
yarn add [package] --peer     # 피어 의존성  
yarn add [package] --optional # 선택적 의존성

# 의존성 업그레이드
yarn upgrade [package]
yarn upgrade [package]@[version]
yarn upgrade [package]@[tag]

# 의존성 제거
yarn remove [package]

# 모든 의존성 설치
yarn
# 또는
yarn install
```

## 버전 관리

### Yarn 4+ 버전 전환
```bash
# 안정 버전으로 전환
yarn set version stable

# Canary 버전으로 전환
yarn set version canary

# 소스에서 빌드
yarn set version from sources
```

### Yarn Classic 버전 관리
Yarn Classic은 일반적으로 npm을 통해 관리됩니다:
```bash
# 최신 버전으로 업그레이드
npm install --global yarn@latest
```

## 모범 사례

### 새 프로젝트 권장사항
- 최신 기능과 성능 개선을 얻기 위해 Yarn 4+ 사용
- 복잡한 프로젝트 구조를 관리하기 위해 워크스페이스 기능을 충분히 활용
- 프로젝트 일관성을 보장하기 위해 제약 조건 사용

### 기존 프로젝트 마이그레이션
- 기존 의존성 및 워크플로우의 호환성 평가
- 비중요 프로젝트에서 먼저 테스트한 후 점진적으로 모던 버전으로 마이그레이션
- Yarn이 제공하는 마이그레이션 도구 및 문서 활용

### 성능 최적화
- Yarn 4+는 병렬 설치 및 오프라인 캐싱을 통해 더 나은 성능 제공
- 워크스페이스의 포커스 설치는 불필요한 의존성 다운로드를 줄임
- 핵심 복잡성을 증가시키지 않고 기능을 확장하기 위해 플러그인 시스템 활용

> **참고**: 이 문서는 yarnpkg.com 및 classic.yarnpkg.com 공식 웹사이트의 콘텐츠를 기반으로 하며, 각 버전의 자세한 사용 방법과 모범 사례를 포함합니다.
