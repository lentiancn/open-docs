# Manuel d'utilisation de Yarn

## Comparaison des commandes de base

### Yarn 4+ (Version moderne) vs Yarn Classic (v1)

| Fonction | Yarn 4+ | Yarn Classic |
|----------|---------|-------------|
| Initialiser le projet | `yarn init -2` | `yarn init` |
| Ajouter une dépendance | `yarn add package` | `yarn add package` |
| Installer les dépendances | `yarn install` | `yarn` ou `yarn install` |
| Supprimer une dépendance | `yarn remove package` | `yarn remove package` |
| Mettre à jour une dépendance | `yarn up package` | `yarn upgrade package` |

## Fonctionnalités avancées de Yarn 4+

### Workspaces

Les workspaces sont le nom des packages individuels qui font partie du même projet et que Yarn installera et liera ensemble pour simplifier les références croisées.

#### Déclaration des Workspaces
Ajoutez un tableau `workspaces` au `package.json` racine :

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

#### Références croisées entre Workspaces
Utilisez le protocole `workspace:` pour établir des dépendances entre workspaces :

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

#### Installations ciblées (Focused Installs)
Installez uniquement les dépendances requises pour des workspaces spécifiques :

```bash
# Installer uniquement @my-org/app et ses dépendances
yarn workspaces focus @my-org/app

# Installer uniquement les dépendances de production
yarn workspaces focus -A --production
```

#### Exécution parallèle
Exécutez des scripts en parallèle sur plusieurs workspaces :

```bash
# Publier tous les packages en parallèle (en respectant l'ordre topologique)
yarn workspaces foreach --all -pt npm publish

# Exécuter lint uniquement sur les workspaces modifiés
yarn workspaces foreach --since run lint

# Exécuter build sur le workspace actuel et ses dépendances
yarn workspaces foreach --from . -R run build
```

### Contraintes (Constraints)
Les contraintes sont utilisées pour déclarer des règles qui doivent s'appliquer à des workspaces spécifiques dans votre projet, similaire à ESLint pour le code :

- Forcer la synchronisation des versions de dépendances dans tout le projet
- Empêcher l'utilisation de certaines dépendances
- Forcer des paramètres appropriés pour des champs comme license, engines.node, etc.

### Scripts globaux
Les noms de scripts contenant des deux-points (`:`) sont traités comme des scripts globaux et peuvent être exécutés depuis n'importe où dans le projet.

## Utilisation de base de Yarn Classic

### Commandes courantes
```bash
# Initialiser un nouveau projet
yarn init

# Ajouter une dépendance
yarn add [package]
yarn add [package]@[version]
yarn add [package]@[tag]

# Ajouter à différentes catégories de dépendances
yarn add [package] --dev      # Dépendances de développement
yarn add [package] --peer     # Dépendances peer  
yarn add [package] --optional # Dépendances optionnelles

# Mettre à jour une dépendance
yarn upgrade [package]
yarn upgrade [package]@[version]
yarn upgrade [package]@[tag]

# Supprimer une dépendance
yarn remove [package]

# Installer toutes les dépendances
yarn
# ou
yarn install
```

## Gestion des versions

### Changement de version dans Yarn 4+
```bash
# Passer à la version stable
yarn set version stable

# Passer à la version Canary
yarn set version canary

# Construire à partir des sources
yarn set version from sources
```

### Gestion des versions dans Yarn Classic
Yarn Classic est généralement géré via npm :
```bash
# Mettre à jour vers la dernière version
npm install --global yarn@latest
```

## Bonnes pratiques

### Recommandations pour les nouveaux projets
- Utilisez Yarn 4+ pour obtenir les dernières fonctionnalités et améliorations de performance
- Exploitez pleinement la fonctionnalité des workspaces pour gérer des structures de projets complexes
- Utilisez les contraintes pour garantir la cohérence du projet

### Migration des projets existants
- Évaluez la compatibilité des dépendances et des flux de travail existants
- Migrez progressivement vers la version moderne, en testant d'abord sur des projets non critiques
- Exploitez les outils et la documentation de migration de Yarn

### Optimisation des performances
- Yarn 4+ offre de meilleures performances grâce aux installations parallèles et à la mise en cache hors ligne
- Les installations ciblées dans les workspaces réduisent les téléchargements inutiles de dépendances
- Exploitez le système de plugins pour étendre les fonctionnalités sans augmenter la complexité du noyau
