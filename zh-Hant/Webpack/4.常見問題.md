# Webpack 常見問題

## 安裝相關問題

### Q: 我應該全域安裝 Webpack 還是本機安裝？
**A**: 始終將 Webpack 作為開發相依進行本機安裝。全域安裝可能導致專案間的版本衝突，並使管理不同 Webpack 版本變得更加困難。

### Q: webpack 和 webpack-cli 有什麼區別？
**A**: 
- **webpack**: 核心打包引擎
- **webpack-cli**: 提供 CLI 命令的命令列介面

基本使用需要兩者。一起安裝：`npm install --save-dev webpack webpack-cli`

## 設定相關問題

### Q: 我需要設定檔嗎？
**A**: 從 Webpack 4 開始，基本使用不需要設定檔。Webpack 將使用預設設定並尋找 `./src/index.js` 作為入口點。然而，大多數實際專案需要自訂設定。

### Q: Webpack 設定中 CommonJS 和 ES Module 的區別是什麼？
**A**: 
- **CommonJS**（Webpack v4 風格）: 使用 `module.exports` 和 `require()`
- **ES Module**（Webpack v5 風格）: 使用 `export default` 和 `import`

Webpack v5 支援兩者，但新專案推薦使用 ES Module。

### Q: 如何處理多個入口點？
**A**: 在 entry 設定中指定物件：

```javascript
export default {
  entry: {
    app: './src/app.js',
    admin: './src/admin.js'
  }
};
```

這將為每個入口點建立單獨的打包檔案。

## 效能相關問題

### Q: 為什麼我的建置速度這麼慢？
**A**: 常見原因及解決方案：
- **龐大的 node_modules**: 使用 `SplitChunksPlugin` 分離供應商程式碼
- **沒有快取**: 在 Webpack v5 中啟用持久化快取
- **載入器過多**: 最佳化載入器設定並使用 include/exclude 規則
- **Source maps**: 在開發中使用更快的 source map 類型（`eval` 代替 `source-map`）

### Q: 如何為生產建置啟用快取？
**A**: 在輸出檔名中使用內容雜湊：

```javascript
output: {
  filename: '[name].[contenthash].js',
  chunkFilename: '[name].[contenthash].js'
}
```

這確保檔案僅在其內容更改時才會更改，允許瀏覽器有效快取它們。

### Q: Webpack v5 中的持久化快取是什麼？
**A**: 持久化快取在執行之間將建置資訊儲存在磁碟上，顯著加快後續建置速度。啟用方式：

```javascript
cache: {
  type: 'filesystem'
}
```

## 開發相關問題

### Q: 如何設定熱模組替換（HMR）？
**A**: 使用啟用了 HMR 的 webpack-dev-server：

```javascript
// webpack.config.js
export default {
  devServer: {
    hot: true
  }
};
```

並在您的應用程式中新增 HMR 程式碼：

```javascript
if (module.hot) {
  module.hot.accept('./module', () => {
    // 處理更新
  });
}
```

### Q: 如何偵錯我的打包程式碼？
**A**: 在設定中啟用 source maps：

```javascript
export default {
  devtool: 'source-map' // 用於生產環境
  // 或
  devtool: 'eval-source-map' // 用於開發環境（更快）
};
```

這允許您在瀏覽器的開發者工具中偵錯原始原始碼。

### Q: 如何處理 CSS 和圖片？
**A**: 使用適當的載入器或 Webpack v5 的內建資源模組：

**Webpack v5（推薦）：**
```javascript
module: {
  rules: [
    {
      test: /\.css$/,
      use: ['style-loader', 'css-loader']
    },
    {
      test: /\.(png|svg|jpg|jpeg|gif)$/i,
      type: 'asset/resource'
    }
  ]
}
```

**Webpack v4：**
```javascript
module: {
  rules: [
    {
      test: /\.css$/,
      use: ['style-loader', 'css-loader']
    },
    {
      test: /\.(png|svg|jpg|jpeg|gif)$/i,
      use: ['file-loader']
    }
  ]
}
```

## 遷移相關問題

### Q: 如何從 Webpack v4 遷移到 v5？
**A**: 按照以下步驟操作：
1. 更新相依：`npm install webpack@latest webpack-cli@latest`
2. 查閱官方遷移指南了解破壞性變更
3. 用資源模組替換 file-loader/url-loader
4. 更新外掛設定以相容 Webpack v5
5. 彻底測試以確保一切正常工作

### Q: Webpack v5 中的 file-loader 和 url-loader 怎麼了？
**A**: Webpack v5 引入了內建資源模組來替換 file-loader 和 url-loader：

- **asset/resource**: 替換 file-loader（輸出單獨的檔案）
- **asset/inline**: 替換 url-loader（以內聯資料 URL 形式）
- **asset**: 根據檔案大小自動選擇 resource 或 inline

### Q: 我現有的外掛與 Webpack v5 相容嗎？
**A**: 大多數流行外掛都已更新以相容 Webpack v5。請檢查外掛的文件或 npm 頁面以了解 Webpack v5 支援。如果外掛不相容，請尋找替代方案或檢查是否有可用的測試版本。

## 進階使用問題

### Q: 什麼是模組聯合（Module Federation）？
**A**: 模組聯合是 Webpack v5 的一個特性，允許在執行階段在 separate 應用程式之間共用程式碼。它特別適用於微前端架構，其中不同的團隊擁有應用程式的不同部分。

### Q: 如何最佳化打包檔案大小？
**A**: 多種策略：
- **程式碼分割**: 將程式碼分割成按需載入的小塊
- **Tree Shaking**: 移除未使用的程式碼（確保您使用的是 ES6 模組）
- **壓縮**: 在生產模式下啟用壓縮
- **壓縮**: 使用壓縮外掛如 CompressionWebpackPlugin
- **分析打包檔案**: 使用 webpack-bundle-analyzer 識別大型相依

### Q: 如何處理環境變數？
**A**: 使用 DefinePlugin 注入環境變數：

```javascript
import webpack from 'webpack';

export default {
  plugins: [
    new webpack.DefinePlugin({
      'process.env.NODE_ENV': JSON.stringify('production'),
      'process.env.API_URL': JSON.stringify('https://api.example.com')
    })
  ]
};
```

這些變數將在建置時被其實際值替換。
