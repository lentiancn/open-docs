# Руководство пользователя Yarn

## Сравнение основных команд

### Yarn 4+ (Современная версия) vs Yarn Classic (v1)

| Функция | Yarn 4+ | Yarn Classic |
|---------|---------|-------------|
| Инициализация проекта | `yarn init -2` | `yarn init` |
| Добавление зависимости | `yarn add package` | `yarn add package` |
| Установка зависимостей | `yarn install` | `yarn` или `yarn install` |
| Удаление зависимости | `yarn remove package` | `yarn remove package` |
| Обновление зависимости | `yarn up package` | `yarn upgrade package` |

## Расширенные функции Yarn 4+

### Рабочие пространства (Workspaces)

Рабочие пространства — это название отдельных пакетов, которые являются частью одного проекта и которые Yarn установит и свяжет вместе для упрощения кросс-ссылок.

#### Объявление рабочих пространств
Добавьте массив `workspaces` в корневой `package.json`:

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

#### Кросс-ссылки между рабочими пространствами
Используйте протокол `workspace:`, чтобы устанавливать зависимости между рабочими пространствами:

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

#### Целенаправленные установки (Focused Installs)
Устанавливайте только зависимости, необходимые для конкретных рабочих пространств:

```bash
# Установить только @my-org/app и его зависимости
yarn workspaces focus @my-org/app

# Установить только производственные зависимости
yarn workspaces focus -A --production
```

#### Параллельное выполнение
Выполняйте скрипты параллельно в нескольких рабочих пространствах:

```bash
# Публиковать все пакеты параллельно (с соблюдением топологического порядка)
yarn workspaces foreach --all -pt npm publish

# Выполнять lint только в измененных рабочих пространствах
yarn workspaces foreach --since run lint

# Выполнять build в текущем рабочем пространстве и его зависимостях
yarn workspaces foreach --from . -R run build
```

### Ограничения (Constraints)
Ограничения используются для объявления правил, которые должны применяться к определенным рабочим пространствам в вашем проекте, аналогично ESLint для кода:

- Принудительная синхронизация версий зависимостей по всему проекту
- Предотвращение использования определенных зависимостей
- Принудительная настройка соответствующих значений для полей, таких как license, engines.node и т.д.

### Глобальные скрипты
Имена скриптов, содержащие двоеточия (`:`), рассматриваются как глобальные скрипты и могут выполняться из любого места внутри проекта.

## Основное использование Yarn Classic

### Общие команды
```bash
# Инициализировать новый проект
yarn init

# Добавить зависимость
yarn add [package]
yarn add [package]@[version]
yarn add [package]@[tag]

# Добавить в разные категории зависимостей
yarn add [package] --dev      # Зависимости разработки
yarn add [package] --peer     # Peer-зависимости  
yarn add [package] --optional # Опциональные зависимости

# Обновить зависимость
yarn upgrade [package]
yarn upgrade [package]@[version]
yarn upgrade [package]@[tag]

# Удалить зависимость
yarn remove [package]

# Установить все зависимости
yarn
# или
yarn install
```

## Управление версиями

### Переключение версий в Yarn 4+
```bash
# Переключиться на стабильную версию
yarn set version stable

# Переключиться на Canary-версию
yarn set version canary

# Собрать из исходников
yarn set version from sources
```

### Управление версиями в Yarn Classic
Yarn Classic обычно управляется через npm:
```bash
# Обновить до последней версии
npm install --global yarn@latest
```

## Лучшие практики

### Рекомендации для новых проектов
- Используйте Yarn 4+, чтобы получить новейшие функции и улучшения производительности
- Полностью используйте функциональность рабочих пространств для управления сложными структурами проектов
- Используйте ограничения для обеспечения согласованности проекта

### Миграция существующих проектов
- Оцените совместимость существующих зависимостей и рабочих процессов
- Постепенно мигрируйте на современную версию, сначала тестируя на некритических проектах
- Используйте инструменты и документацию по миграции Yarn

### Оптимизация производительности
- Yarn 4+ обеспечивает лучшую производительность благодаря параллельным установкам и офлайн-кэшированию
- Целенаправленные установки в рабочих пространствах уменьшают ненужные загрузки зависимостей
- Используйте систему плагинов для расширения функциональности без увеличения сложности ядра

> **Примечание**: Этот документ основан на официальном контенте сайтов yarnpkg.com и classic.yarnpkg.com и включает подробные методы использования и лучшие практики для каждой версии.
