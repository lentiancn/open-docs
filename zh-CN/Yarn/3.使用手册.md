# Yarn 使用手册

## 基本命令对比

### Yarn 4+ (现代版本) vs Yarn Classic (v1)

| 功能 | Yarn 4+ | Yarn Classic |
|------|---------|-------------|
| 初始化项目 | `yarn init -2` | `yarn init` |
| 添加依赖 | `yarn add package` | `yarn add package` |
| 安装依赖 | `yarn install` | `yarn` 或 `yarn install` |
| 移除依赖 | `yarn remove package` | `yarn remove package` |
| 升级依赖 | `yarn up package` | `yarn upgrade package` |

## Yarn 4+ 高级功能

### 工作区 (Workspaces)

工作区是同一项目中各个独立包的名称，Yarn 会将它们安装并链接在一起以简化交叉引用。

#### 声明工作区
在根目录的 `package.json` 中添加 `workspaces` 数组：

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

#### 工作区交叉引用
使用 `workspace:` 协议在工作区之间建立依赖关系：

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

#### 聚焦安装 (Focused Installs)
只安装特定工作区所需的依赖：

```bash
# 只安装 @my-org/app 及其依赖
yarn workspaces focus @my-org/app

# 只安装生产依赖
yarn workspaces focus -A --production
```

#### 并行执行
在多个工作区中并行运行脚本：

```bash
# 在所有工作区中发布包（按拓扑顺序）
yarn workspaces foreach --all -pt npm publish

# 只对修改过的工作区运行 lint
yarn workspaces foreach --since run lint

# 对当前工作区及其依赖运行构建
yarn workspaces foreach --from . -R run build
```

### 约束 (Constraints)
约束用于声明必须应用于项目中特定工作区的规则，类似于代码的 ESLint：

- 强制同步所有依赖版本
- 禁止使用某些依赖
- 强制设置 license、engines.node 等字段

### 全局脚本
包含冒号 (`:`) 的脚本名称被视为全局脚本，可以从项目中的任何位置运行。

## Yarn Classic 基本用法

### 常用命令
```bash
# 初始化新项目
yarn init

# 添加依赖
yarn add [package]
yarn add [package]@[version]
yarn add [package]@[tag]

# 添加到不同类别的依赖
yarn add [package] --dev      # 开发依赖
yarn add [package] --peer     # 同等依赖  
yarn add [package] --optional # 可选依赖

# 升级依赖
yarn upgrade [package]
yarn upgrade [package]@[version]
yarn upgrade [package]@[tag]

# 移除依赖
yarn remove [package]

# 安装所有依赖
yarn
# 或
yarn install
```

## 版本管理

### Yarn 4+ 版本切换
```bash
# 切换到稳定版本
yarn set version stable

# 切换到 Canary 版本
yarn set version canary

# 从源码构建
yarn set version from sources
```

### Yarn Classic 版本管理
Yarn Classic 通常通过 npm 进行版本管理：
```bash
# 升级到最新版本
npm install --global yarn@latest
```

## 最佳实践

### 新项目建议
- 使用 Yarn 4+ 以获得最新的功能和性能改进
- 充分利用工作区功能管理复杂的项目结构
- 使用约束确保项目一致性

### 现有项目迁移
- 评估现有依赖和工作流程的兼容性
- 逐步迁移到现代版本，先在非关键项目中测试
- 利用 Yarn 提供的迁移工具和文档

### 性能优化
- Yarn 4+ 的并行安装和离线缓存提供更好的性能
- 工作区的聚焦安装减少不必要的依赖下载
- 利用插件系统扩展功能而不增加核心复杂性

> **注意**: 本文档基于官方 yarnpkg.com 和 classic.yarnpkg.com 网站内容整理，包含各版本的详细使用方法和最佳实践。
