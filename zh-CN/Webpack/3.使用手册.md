# Webpack 使用手册

## 核心概念

### 入口点

入口点指示 Webpack 应该使用哪个模块来开始构建其内部依赖关系图。默认值为 `./src/index.js`，但您可以指定不同的（或多个）入口点。

**单入口：**
```javascript
// webpack.config.js
export default {
  entry: './path/to/my/entry/file.js',
};
```

**多入口：**
```javascript
export default {
  entry: {
    app: './src/app.js',
    admin: './src/admin.js'
  }
};
```

### 输出配置

output 属性告诉 Webpack 将打包文件输出到何处以及如何命名。默认输出文件为 `./dist/main.js`。

```javascript
import path from "node:path";

export default {
  entry: './path/to/my/entry/file.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'my-first-webpack.bundle.js',
  },
};
```

### 加载器（Loaders）

加载器允许 Webpack 处理非 JavaScript 文件，并将其转换为有效模块。

**基本加载器配置：**
```javascript
export default {
  module: {
    rules: [
      { test: /\.txt$/, use: 'raw-loader' },
      { test: /\.css$/, use: ['style-loader', 'css-loader'] },
      { test: /\.(png|svg|jpg|jpeg|gif)$/i, type: 'asset/resource' }
    ],
  },
};
```

### 插件（Plugins）

插件执行更广泛的任务，如打包文件优化、资源管理和环境变量注入。

**常用插件：**
```javascript
import HtmlWebpackPlugin from "html-webpack-plugin";
import MiniCssExtractPlugin from "mini-css-extract-plugin";
import webpack from "webpack";

export default {
  plugins: [
    new HtmlWebpackPlugin({ template: './src/index.html' }),
    new MiniCssExtractPlugin(),
    new webpack.DefinePlugin({
      'process.env.NODE_ENV': JSON.stringify('production')
    })
  ],
};
```

### 模式（Mode）

mode 参数启用内置优化：

- **development**: 启用有用的错误消息和快速重建
- **production**: 启用压缩、作用域提升和其他优化
- **none**: 禁用所有默认优化

```javascript
export default {
  mode: 'production',
};
```

## 高级功能

### 代码分割

Webpack 提供了多种代码分割方式：

**入口点：**
通过创建多个入口点手动分割代码。

**防止重复：**
使用 `SplitChunksPlugin` 移除重复依赖。

**动态导入：**
使用动态导入按需分割代码：
```javascript
// 之前
import _ from 'lodash';

// 之后
const _ = await import('lodash');
```

### 缓存

Webpack 提供了多种缓存策略：

- **输出文件名**: 使用 `[contenthash]` 创建唯一文件名
- **SplitChunks**: 分离供应商代码和应用代码
- **运行时块**: 将 Webpack 运行时提取到单独的块中

### 开发工具

**Source Maps：**
启用 source maps 以便于调试：
```javascript
export default {
  devtool: 'inline-source-map',
};
```

**开发服务器：**
使用 webpack-dev-server 实现实时重载：
```bash
npm install --save-dev webpack-dev-server
```

```javascript
// package.json
{
  "scripts": {
    "start": "webpack serve --open"
  }
}
```

## 配置文件

### 基本配置

```javascript
// webpack.config.js
import path from "node:path";

export default {
  entry: './src/index.js',
  output: {
    filename: 'bundle.js',
    path: path.resolve(__dirname, 'dist'),
  },
  module: {
    rules: [
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader']
      }
    ]
  },
  plugins: [],
  mode: 'development'
};
```

### 环境特定配置

为不同环境创建单独的配置：

- `webpack.common.js`: 共享配置
- `webpack.dev.js`: 开发环境特定设置
- `webpack.prod.js`: 生产环境特定设置

使用 webpack-merge 合并配置：
```javascript
import { merge } from 'webpack-merge';
import common from './webpack.common.js';

export default merge(common, {
  mode: 'development',
  devtool: 'inline-source-map',
});
```

## 版本差异

### Webpack v5 与 Webpack v4

| 功能 | Webpack v5 | Webpack v4 |
|------|------------|------------|
| **模块系统** | ES Module + CommonJS | 仅 CommonJS |
| **缓存** | 持久化缓存 | 内存缓存 |
| **资源处理** | 内置资源模块 | 需要 file-loader/url-loader |
| **性能** | 使用持久化缓存，构建更快 | 标准性能 |
| **模块联合** | 内置支持 | 不可用 |
| **Node.js 支持** | Node.js 10.13.0+ | Node.js 6.11.5+ |

### 迁移注意事项

- 更新加载器配置，使用资源模块而不是 file-loader/url-loader
- 检查插件与 Webpack v5 的兼容性
- 如果迁移到 ES Module，更新配置语法
- 彻底测试，因为某些插件可能存在破坏性变更
