# Oracle Database 자주 묻는 질문

## 설치 관련 질문

### Q1: 설치 중 권한 오류가 발생하면 어떻게 해야 하나요?
**A**: oracle 사용자로 설치를 실행하고, 해당 사용자가 oinstall 및 dba 그룹에 속해 있는지 확인하세요. `/etc/passwd` 및 `/etc/group` 파일에서 사용자 및 그룹 설정을 확인하세요.

### Q2: 설치 시 메모리 부족 오류를 해결하려면 어떻게 해야 하나요?
**A**: Oracle Database는 충분한 메모리를 필요로 합니다. 해결 방법은 다음과 같습니다:
- 시스템 물리적 메모리 증가
- 커널 파라미터 조정: `kernel.shmmax` 및 `kernel.shmall`
- 설치 시 더 작은 구성 옵션 선택 (예: 데스크톱 클래스 설치)

### Q3: Docker에서 Oracle Database를 실행하려면 어떻게 해야 하나요?
**A**: 오라클은 공식 Docker 이미지를 제공합니다:
```bash
# Oracle Database Free (19c)
docker pull container-registry.oracle.com/database/free:19.3.0.0
docker run -d -p 1521:1521 --name oracle-free container-registry.oracle.com/database/free:19.3.0.0

# 참고: 초기 시작에는 초기화에 상당한 시간이 걸릴 수 있습니다
```

## 연결 문제

### Q4: ORA-12541: TNS:no listener 오류를 해결하려면 어떻게 해야 하나요?
**A**: 이 오류는 리스너가 실행되지 않고 있음을 나타냅니다. 해결 방법:
```bash
# 리스너 시작
lsnrctl start

# 리스너 상태 확인
lsnrctl status

# 리스너 설정이 올바른지 확인 (listener.ora 파일)
```

### Q5: ORA-12170: TNS:Connect timeout occurred 오류가 발생하면?
**A**: 네트워크 연결 시간 초과입니다. 다음을 확인하세요:
- 데이터베이스 서버 접근 가능성 (ping 테스트)
- 방화벽이 포트 1521을 차단하지 않는지
- 리스너가 올바른 IP 주소에서 수신 대기 중인지
- tnsnames.ora 설정의 정확성

### Q6: sys/system 비밀번호를 재설정하려면 어떻게 해야 하나요?
**A**: orapwd 도구를 사용하여 비밀번호 파일을 재설정하세요:
```bash
# 데이터베이스 중지
sqlplus / as sysdba
SHUTDOWN IMMEDIATE;

# 비밀번호 파일 재생성
orapwd file=$ORACLE_HOME/dbs/orapw$ORACLE_SID password=new_password force=y

# 데이터베이스 시작
STARTUP;
```

## 성능 문제

### Q7: 느린 쿼리를 최적화하려면 어떻게 해야 하나요?
**A**: 성능 최적화 단계:
1. **실행 계획 분석**: `EXPLAIN PLAN`을 사용하여 쿼리 실행 경로 확인
2. **인덱스 확인**: WHERE 절의 열에 적절한 인덱스가 있는지 확인
3. **통계 정보 수집**: `EXEC DBMS_STATS.GATHER_TABLE_STATS`
4. **SQL 튜닝 어드바이저**: Oracle SQL Tuning Advisor 사용
5. **대기 이벤트 확인**: `v$session_wait` 뷰 조회

### Q8: 현재 실행 중인 느린 쿼리를 확인하려면 어떻게 해야 하나요?
**A**: v$session 및 v$sql 뷰를 조회하세요:
```sql
SELECT s.sid, s.serial#, s.username, s.status, 
       q.sql_text, q.elapsed_time, q.cpu_time
FROM v$session s, v$sql q
WHERE s.sql_id = q.sql_id
  AND s.status = 'ACTIVE'
  AND q.elapsed_time > 1000000; -- 실행 시간이 1초 이상인 경우
```

### Q9: 메모리 사용량이 너무 높으면 어떻게 해야 하나요?
**A**: 메모리 파라미터를 조정하세요:
- **SGA_TARGET**: 시스템 전역 영역 총 크기
- **PGA_AGGREGATE_TARGET**: 프로그램 전역 영역 총 크기
- **MEMORY_TARGET**: 자동 메모리 관리 (11g 이상)

```sql
-- 현재 메모리 사용량 확인
SHOW PARAMETER memory;
SHOW PARAMETER sga;
SHOW PARAMETER pga;

-- 동적 조정 (sysdba 권한 필요)
ALTER SYSTEM SET MEMORY_TARGET = 4G SCOPE=BOTH;
```

## 백업 및 복구 문제

### Q10: RMAN 백업 실패를 처리하려면 어떻게 해야 하나요?
**A**: 일반적인 RMAN 문제 해결:
- **공간 부족**: 백업 대상 디렉토리 공간 확인
- **권한 문제**: oracle 사용자가 백업 디렉토리에 쓰기 권한이 있는지 확인
- **아카이브 로그 누락**: 모든 아카이브 로그를 사용할 수 있는지 확인
- **채널 설정**: RMAN 채널 설정이 올바른지 확인

### Q11: 실수로 삭제한 테이블을 복구하려면 어떻게 해야 하나요?
**A**: 복구 방법은 백업 전략에 따라 다릅니다:
1. **플래시백 테이블** (활성화된 경우):
   ```sql
   FLASHBACK TABLE table_name TO BEFORE DROP;
   ```
2. **RMAN 시점 복구**:
   ```rman
   RUN {
       SET UNTIL TIME "TO_DATE('2026-03-30 08:00:00', 'YYYY-MM-DD HH24:MI:SS')";
       RESTORE DATABASE;
       RECOVER DATABASE;
   }
   ```
3. **Data Pump 가져오기**: 최근 내보내기 파일에서 복구

## 버전 차이

### Q12: Oracle Database 19c와 26ai의 주요 차이점은 무엇인가요?
**A**: 주요 차이점은 다음과 같습니다:
- **AI 기능**: 26ai는 AI 기반 자동화 관리 기능을 통합
- **성능 최적화**: 26ai는 더 스마트한 리소스 관리 및 쿼리 최적화 제공
- **보안**: 26ai는 보안 모니터링 및 위협 탐지 기능 강화
- **클라우드 네이티브 지원**: 26ai는 컨테이너화 및 클라우드 환경에 대한 지원 향상

### Q13: 19c에서 26ai로 업그레이드할 때 주의해야 할 사항은 무엇인가요?
**A**: 업그레이드 고려사항:
- **호환성 확인**: Database Upgrade Assistant(DBUA)를 사용하여 사전 검사 수행
- **백업**: 업그레이드 전 반드시 전체 데이터베이스 백업 수행
- **테스트 환경**: 먼저 테스트 환경에서 업그레이드 프로세스 검증
- **애플리케이션 호환성**: 애플리케이션이 새 버전과 호환되는지 확인
- **라이선스**: 새 버전의 라이선스 요구사항 확인

## 일상적인 유지보수

### Q14: 아카이브 로그를 정리하려면 어떻게 해야 하나요?
**A**: 아카이브 로그 정리 방법:
```bash
# RMAN을 사용하여 백업된 아카이브 로그 삭제
rman target /
DELETE ARCHIVELOG ALL COMPLETED BEFORE 'SYSDATE-7';

# 수동 삭제 (백업되었음을 확신하는 경우에만 권장)
rm $ORACLE_BASE/fast_recovery_area/*/archivelog/*.arc
```

### Q15: 테이블스페이스가 가득 차면 어떻게 해야 하나요?
**A**: 테이블스페이스 확장 방법:
```sql
-- 데이터 파일 추가
ALTER TABLESPACE users ADD DATAFILE '/u01/app/oracle/oradata/ORCL/users02.dbf' SIZE 1G;

-- 기존 데이터 파일 크기 조정
ALTER DATABASE DATAFILE '/u01/app/oracle/oradata/ORCL/users01.dbf' RESIZE 2G;

-- 자동 확장 활성화
ALTER DATABASE DATAFILE '/u01/app/oracle/oradata/ORCL/users01.dbf' AUTOEXTEND ON NEXT 100M MAXSIZE UNLIMITED;
```

### Q16: 데이터베이스 상태를 모니터링하려면 어떻게 해야 하나요?
**A**: 상태 모니터링 방법:
- **AWR 보고서**: 정기적으로 AWR 보고서 생성 및 분석
- **ADDM 보고서**: 자동 데이터베이스 진단 모니터
- **OEM**: Oracle Enterprise Manager
- **사용자 정의 스크립트**: 주요 지표(세션 수, 잠금, 테이블스페이스 사용량 등) 모니터링

## 문제 해결

### Q17: 데이터베이스가 시작되지 않으면 어떻게 해야 하나요?
**A**: 시작 문제 해결 단계:
1. **alert log 확인**: `$ORACLE_BASE/diag/rdbms/<DB_NAME>/trace/alert_<SID>.log`
2. **제어 파일 확인**: 제어 파일이 존재하고 접근 가능한지 확인
3. **데이터 파일 확인**: 모든 데이터 파일이 존재하는지 확인
4. **파라미터 파일 확인**: spfile 또는 pfile 설정이 올바른지 확인
5. **mount 모드 시도**: `STARTUP MOUNT` 후 단계별로 문제 해결

### Q18: 교착 상태(deadlock)가 발생하면 어떻게 해야 하나요?
**A**: 교착 상태 처리 방법:
- **자동 처리**: Oracle이 자동으로 감지하여 트랜잭션 중 하나를 종료
- **수동 개입**: `v$lock` 및 `v$session`을 조회하여 차단 세션을 찾아 kill
  ```sql
  ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE;
  ```
- **예방 조치**: 애플리케이션 수준에서 일관된 접근 순서 보장

## 라이선스 및 비용

### Q19: Oracle Database 무료 버전의 제한 사항은 무엇인가요?
**A**: Oracle Database Free (19c/26ai) 제한 사항:
- **CPU 제한**: 최대 2개 CPU
- **메모리 제한**: 최대 2GB RAM
- **스토리지 제한**: 최대 12GB 사용자 데이터
- **기능 제한**: 엔터프라이즈 에디션 고급 기능(RAC, Data Guard 등) 미포함

### Q20: Oracle 라이선스 비용을 줄이려면 어떻게 해야 하나요?
**A**: 비용 최적화 전략:
- **무료 버전 사용**: 개발 및 소규모 프로덕션 환경용
- **CPU 라이선스 적절히 계획**: 실제 사용량 기반으로 구매
- **클라우드 서비스 고려**: OCI, AWS RDS 등의 종량제 모델
- **정기 감사**: 라이선스 규정 준수 확인 및 과도한 사용 방지
