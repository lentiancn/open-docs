# SQLite よくある質問 (FAQ)

## 一般的な質問

### Q: SQLite とは何ですか？

A: SQLite は軽量で自己完結型の SQL データベースエンジンです。サーバーを必要とせず、設定不要で、単一のファイルにデータベース全体を格納します。パブリックドメインであり、商用および非商用の両方の用途で自由に使用できます。

### Q: SQLite は無料で使用できますか？

A: はい、SQLite はパブリックドメインにあり、著作権表示やライセンス料なしで自由に使用、修正、配布できます。商用製品にも制限なく組み込むことができます。

### Q: SQLite の制限事項は何ですか？

A: 主な制限事項は以下の通りです：
- 同時に1つの書き込みプロセスしか許可されません（WALモードでは読み取りは並行可能）
- 高度なユーザー管理機能はありません（ファイルシステムレベルのアクセス制御に依存）
- 暗号化機能は標準では提供されていません
- 最大データベースサイズは140TBです

## 技術的な質問

### Q: SQLite はどのくらいのデータ量を扱えますか？

A: SQLite は最大140TBのデータベースサイズをサポートしています。ただし、実際のパフォーマンスは使用するハードウェアやクエリの複雑さに依存します。一般的に、小規模から中規模のアプリケーションには十分な性能を提供します。

### Q: 複数のアプリケーションから同時に SQLite データベースにアクセスできますか？

A: はい、複数のプロセスが同時に SQLite データベースを読み取ることができます。ただし、書き込み操作は一度に1つのプロセスのみが実行できます。WAL（Write-Ahead Logging）モードを有効にすることで、読み取りと書き込みの同時実行性が向上します。

### Q: SQLite でトランザクションはサポートされていますか？

A: はい、SQLite は完全なACID（原子性、一貫性、分離性、耐久性）準拠のトランザクションをサポートしています。BEGIN、COMMIT、ROLLBACK コマンドを使用してトランザクションを制御できます。

### Q: SQLite のバックアップ方法を教えてください。

A: SQLite データベースのバックアップにはいくつかの方法があります：

1. **ファイルコピー**: データベースファイルを単純にコピーする（アプリケーションがデータベースを使用していない場合）
2. **オンラインバックアップ API**: アプリケーションが実行中の状態でバックアップを作成
3. **.dump コマンド**: SQL スクリプト形式でエクスポート
   ```bash
   sqlite3 database.db .dump > backup.sql
   ```

### Q: SQLite データベースが破損した場合はどうすればよいですか？

A: まず `PRAGMA integrity_check;` を実行して整合性を確認してください。軽微な問題の場合は `VACUUM;` コマンドで修復できることがあります。重大な破損の場合は、バックアップから復元する必要があります。

## パフォーマンスに関する質問

### Q: SQLite のパフォーマンスを向上させる方法はありますか？

A: 以下の方法でパフォーマンスを改善できます：

- **インデックスの適切な使用**: 頻繁に検索条件として使用されるカラムにインデックスを作成
- **トランザクションのバッチ処理**: 複数の操作を単一のトランザクション内で実行
- **PRAGMA 設定の最適化**:
  ```sql
  PRAGMA journal_mode=WAL;
  PRAGMA synchronous=NORMAL;
  PRAGMA cache_size=10000;
  ```
- **不要なインデックスの削除**: インデックスは更新時のオーバーヘッドになります

### Q: 大量のデータを挿入する際にパフォーマンスが悪いのですが？

A: 大量の INSERT 操作を行う場合は、以下の対策を試してください：

1. **トランザクション内での実行**:
   ```sql
   BEGIN TRANSACTION;
   INSERT INTO table VALUES (...);
   INSERT INTO table VALUES (...);
   -- ... 多数の INSERT ...
   COMMIT;
   ```
2. **PRAGMA 設定の調整**:
   ```sql
   PRAGMA synchronous=OFF;  -- 注意: 安全性が低下します
   PRAGMA journal_mode=MEMORY;
   ```

## 開発に関する質問

### Q: C/C++ アプリケーションで SQLite を使用するには？

A: SQLite は C 言語で記述されており、C/C++ アプリケーションに直接組み込むことができます。公式サイトから amalgamation ソースコードをダウンロードし、プロジェクトに追加するだけで使用できます。

基本的な使用例：
```c
#include "sqlite3.h"
sqlite3 *db;
int rc = sqlite3_open("test.db", &db);
// SQL 実行...
sqlite3_close(db);
```

### Q: Python で SQLite を使用する方法を教えてください。

A: Python には標準ライブラリとして `sqlite3` モジュールが含まれています：

```python
import sqlite3

# データベース接続
conn = sqlite3.connect('example.db')
cursor = conn.cursor()

# テーブル作成
cursor.execute('''CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)''')

# データ挿入
cursor.execute("INSERT INTO users (name) VALUES (?)", ("山田太郎",))

# データ取得
cursor.execute("SELECT * FROM users")
print(cursor.fetchall())

# コミットとクローズ
conn.commit()
conn.close()
```

### Q: SQLite で全文検索は可能ですか？

A: はい、SQLite は FTS3 および FTS5 という全文検索モジュールを提供しています：

```sql
-- FTS5 仮想テーブルの作成
CREATE VIRTUAL TABLE documents USING fts5(title, content);

-- データ挿入
INSERT INTO documents VALUES ('ドキュメントタイトル', '本文内容...');

-- 全文検索
SELECT * FROM documents WHERE documents MATCH '検索キーワード';
```

## 移行と互換性

### Q: MySQL/PostgreSQL から SQLite への移行は可能ですか？

A: 基本的な SQL 構文は互換性がありますが、データ型や特定の関数に違いがあるため、完全な移行には手動での調整が必要です。スキーマとデータをエクスポートし、SQLite の構文に合わせて修正する必要があります。

### Q: SQLite のバージョン間で互換性はありますか？

A: SQLite は後方互換性を非常に重視しており、古いバージョンで作成されたデータベースファイルは新しいバージョンで問題なく読み取れます。ただし、新しい機能を使用したデータベースは古いバージョンでは正しく動作しない可能性があります。

## セキュリティに関する質問

### Q: SQLite データベースを暗号化する方法はありますか？

A: SQLite 自体は暗号化機能を提供していませんが、サードパーティのソリューションとして SQLCipher があります。SQLCipher は SQLite の拡張として、AES-256 暗号化を提供します。

### Q: SQLite の SQL インジェクション対策はどうすればよいですか？

A: すべてのアプリケーションでパラメータ化クエリ（プリペアドステートメント）を使用してください。文字列連結によるクエリ構築は絶対に避けてください。

Python の例：
```python
# 正しい方法（安全）
cursor.execute("SELECT * FROM users WHERE name = ?", (user_input,))

# 危険な方法（避けるべき）
cursor.execute(f"SELECT * FROM users WHERE name = '{user_input}'")
```

A: SQLite は D. Richard Hipp 氏によって開発・保守されています。現在は SQLite Development Team によって継続的に開発されています。

### Q: SQLite のテストは十分に行われていますか？

A: はい、SQLite は非常に広範なテストスイートを持っており、コードカバレッジは99%以上です。多くの企業や組織で実績があり、信頼性の高いデータベースエンジンとして知られています。

### Q: SQLite の今後のロードマップはありますか？

A: SQLite チームは安定性と信頼性を最優先しており、急激な変更よりも慎重な進化を重視しています。詳細なロードマップについては、[SQLite 公式ウェブサイト](https://www.sqlite.org/)をご覧ください。
