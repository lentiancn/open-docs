# Yarn Benutzerhandbuch

## Grundlegende Befehlsvergleich

### Yarn 4+ (Moderne Version) vs Yarn Classic (v1)

| Funktion | Yarn 4+ | Yarn Classic |
|----------|---------|-------------|
| Projekt initialisieren | `yarn init -2` | `yarn init` |
| Abhängigkeit hinzufügen | `yarn add package` | `yarn add package` |
| Abhängigkeiten installieren | `yarn install` | `yarn` oder `yarn install` |
| Abhängigkeit entfernen | `yarn remove package` | `yarn remove package` |
| Abhängigkeit aktualisieren | `yarn up package` | `yarn upgrade package` |

## Fortgeschrittene Funktionen von Yarn 4+

### Workspaces

Workspaces sind der Name einzelner Pakete, die Teil desselben Projekts sind und von Yarn installiert und miteinander verknüpft werden, um Querverweise zu vereinfachen.

#### Workspaces deklarieren
Fügen Sie dem Wurzel-`package.json` ein `workspaces`-Array hinzu:

```json
{
  "workspaces": [
    "packages/*"
  ]
}
```

#### Querverweise zwischen Workspaces
Verwenden Sie das `workspace:`-Protokoll, um Abhängigkeiten zwischen Workspaces herzustellen:

```json
{
  "dependencies": {
    "@my-org/utils": "workspace:^"
  }
}
```

#### Fokussierte Installationen (Focused Installs)
Installieren Sie nur die für bestimmte Workspaces erforderlichen Abhängigkeiten:

```bash
# Nur @my-org/app und seine Abhängigkeiten installieren
yarn workspaces focus @my-org/app

# Nur Produktionsabhängigkeiten installieren
yarn workspaces focus -A --production
```

#### Parallele Ausführung
Führen Sie Skripte parallel über mehrere Workspaces aus:

```bash
# Alle Pakete parallel veröffentlichen (unter Beachtung der topologischen Reihenfolge)
yarn workspaces foreach --all -pt npm publish

# Lint nur auf geänderten Workspaces ausführen
yarn workspaces foreach --since run lint

# Build auf aktuellem Workspace und seinen Abhängigkeiten ausführen
yarn workspaces foreach --from . -R run build
```

### Einschränkungen (Constraints)
Einschränkungen werden verwendet, um Regeln zu definieren, die für bestimmte Workspaces in Ihrem Projekt gelten müssen, ähnlich wie ESLint für Code:

- Synchronisierung von Abhängigkeitsversionen im gesamten Projekt erzwingen
- Verwendung bestimmter Abhängigkeiten verhindern
- Richtige Einstellungen für Felder wie license, engines.node usw. erzwingen

### Globale Skripte
Skriptnamen, die Doppelpunkte (`:`) enthalten, werden als globale Skripte behandelt und können von überall innerhalb des Projekts ausgeführt werden.

## Grundlegende Verwendung von Yarn Classic

### Häufige Befehle
```bash
# Neues Projekt initialisieren
yarn init

# Abhängigkeit hinzufügen
yarn add [package]
yarn add [package]@[version]
yarn add [package]@[tag]

# Zu verschiedenen Abhängigkeitskategorien hinzufügen
yarn add [package] --dev      # Entwicklungsabhängigkeiten
yarn add [package] --peer     # Peer-Abhängigkeiten  
yarn add [package] --optional # Optionale Abhängigkeiten

# Abhängigkeit aktualisieren
yarn upgrade [package]
yarn upgrade [package]@[version]
yarn upgrade [package]@[tag]

# Abhängigkeit entfernen
yarn remove [package]

# Alle Abhängigkeiten installieren
yarn
# oder
yarn install
```

## Versionsverwaltung

### Versionswechsel bei Yarn 4+
```bash
# Auf stabile Version wechseln
yarn set version stable

# Auf Canary-Version wechseln
yarn set version canary

# Aus Quellen bauen
yarn set version from sources
```

### Versionsverwaltung bei Yarn Classic
Yarn Classic wird normalerweise über npm verwaltet:
```bash
# Auf neueste Version aktualisieren
npm install --global yarn@latest
```

## Best Practices

### Empfehlungen für neue Projekte
- Verwenden Sie Yarn 4+, um die neuesten Funktionen und Leistungsverbesserungen zu erhalten
- Nutzen Sie die Workspace-Funktionalität vollständig, um komplexe Projektstrukturen zu verwalten
- Verwenden Sie Einschränkungen, um die Projektkonsistenz sicherzustellen

### Migration bestehender Projekte
- Bewerten Sie die Kompatibilität vorhandener Abhängigkeiten und Arbeitsabläufe
- Migrieren Sie schrittweise zur modernen Version und testen Sie zuerst an nicht kritischen Projekten
- Nutzen Sie die Migrationswerkzeuge und Dokumentation von Yarn

### Leistungsoptimierung
- Yarn 4+ bietet bessere Leistung durch parallele Installationen und Offline-Caching
- Fokussierte Installationen in Workspaces reduzieren unnötige Abhängigkeits-Downloads
- Nutzen Sie das Plugin-System, um Funktionalitäten zu erweitern, ohne die Kernkomplexität zu erhöhen

> **Hinweis**: Dieses Dokument basiert auf offiziellen Inhalten der Websites yarnpkg.com und classic.yarnpkg.com und enthält detaillierte Verwendungsmethoden und Best Practices für jede Version.
